# 「序」模块关联与业务逻辑审查

审查日期：2026-10-03；对应版本：0.4.2（Build 6）。

## 1. 核心业务链路

```text
收集箱（待安排） ──安排日期──→ 今日 / 日历计划
                              │
蓝图 → 阶段 → 里程碑 ──关联──→ 任务 ──完成 / 取消 / 延期──→ 已处理
                              │                             │
                              └──────────当日状态与项目归类──→ 日报
纪念日 ──生成准备任务───────────┘
AI 解析 / 生成蓝图 / 重新规划 ──预览确认──→ 同一套任务和蓝图数据
SwiftData ←→ TaskStore ←→ 页面；JSON 备份 / 文件夹同步使用工作区快照。
```

`TaskStore` 是业务数据入口。页面读取它的任务、蓝图、阶段、里程碑、纪念日、日报；用户操作也经由它修改数据。SwiftData 保存业务数据，`AppPreferences` 用 `UserDefaults` 保存界面和连接配置，DeepSeek API Key 放在钥匙串。

## 2. 各模块职责与口径

| 模块 | 当前职责 | 关键关联 |
| --- | --- | --- |
| 收集箱 | 展示状态为“待安排”的任务 | 从任务编辑器选择“暂不安排日期”；可在任务菜单中安排到今天 |
| 今日 | 展示今天安排的任务、仍未处理的逾期任务、今天完成的任务 | 按蓝图分组；进度、菜单栏和日报读取同一套任务状态 |
| 蓝图 | 管理目标、阶段、里程碑和关联任务 | 今日行动优先展示；任务完成率作为蓝图实际进度 |
| 四象限 | 按重要和紧急程度观察仍需处理的任务 | 与今日、蓝图共享任务，不创建另一份副本 |
| 日历计划 | 查看未来 7/30 天的已安排任务 | 待安排任务不占日历容量 |
| 已处理 | 查看当天完成、取消和延期的任务 | “完成”计入完成数，“取消”不计入完成率 |
| 日报 | 汇总当日计划和已处理事项 | 已关联蓝图的任务按蓝图名称归并项目标题；允许补充和编辑 |
| 纪念日 | 倒计时、提醒、生成准备任务 | 可关联蓝图；准备任务进入统一任务流 |
| AI | 解析任务、生成蓝图、提出重新规划建议 | 先预览再提交；重新规划仅能改当前蓝图的未完成、已安排、未锁定任务 |
| 备份/同步 | 导出、恢复或文件夹同步工作区快照 | 读取失败向上报告，快照检查各类实体 ID 唯一性 |

## 3. 本轮已修正的问题

1. 收集箱原先重复展示今日待办，未真正承载“待安排”状态；现已建立可保存、可快速安排的待安排流。
2. 逾期任务原先离开今日列表；现在持续显示直到完成、取消或延期。
3. 补记已完成事项原先无法直接归入蓝图；现在可选择蓝图并参与蓝图进度。
4. 日报原先可能把同一蓝图下、项目字段不同的任务拆散；生成时统一采用蓝图名称，不修改原任务项目字段。
5. 空数据库重启原先会重新生成演示任务；已移除自动填充，并保留一次性的旧版迁移。
6. 数据库读取和保存错误原先会被吞掉；读取会显式失败，保存失败会在界面提示。
7. “延期到明天”原先可能从任务原日期加一天；现按当前日期计算明天，并保留原计划日期。
8. 批量重新规划原先会移动锁定任务；现在跳过已锁定和未安排任务。
9. AI 重新规划原先可能应用到其他蓝图或已取消任务；现在只允许修改当前蓝图的合格任务。
10. 删除任务/蓝图时清理依赖、父子任务、纪念日蓝图等关联；复制蓝图时重置完成与阻塞历史。
11. AI 计划变更之后若又产生新数据，撤销会拒绝执行，避免把新增事项一并覆盖。

## 4. 下一轮值得做的结构性改进

以下属于较大范围的架构改造，本轮未迁移用户数据结构：

1. **事务性恢复与同步。** 目前工作区快照按实体类型依次写入 SwiftData；如果中途写入失败，可能形成部分恢复。应将快照校验、关联校验和写入放入统一事务，并在失败时回滚。
2. **状态事件历史。** 任务只保存当前状态与少数时间戳，难以准确复盘任意历史日期的取消、延期、恢复次数。应增加不可变的任务事件，再由事件生成历史统计。
3. **计划层级进度。** 蓝图实际进度目前按未取消任务完成数计算，里程碑仍由用户手动确认。应明确阶段、里程碑的验收口径，并区分“任务完成率”和“目标验收进度”。
4. **日报字数边界。** AI 二次修订后仍可能超出设定范围，当前会提示编辑；自动补足的本地兜底也可能偏长。应使用结构化草稿、逐段长度预算和最终校验，保证三段格式与配置范围同时成立。
5. **模块拆分。** `TaskStore` 同时负责状态流转、蓝图、纪念日、日报和数据同步。应将纯业务规则拆成独立服务，保留单一数据入口，减少页面对存储细节的耦合。

## 5. 验证

已运行 `swift test`，23 项测试通过。新增回归覆盖待安排/逾期/当天完成的展示口径、AI 重新规划作用范围、日报蓝图归类、备份重复 ID 拒绝，以及 SwiftData 删除后仍保持空数据。
