# 落地与验收

规范完成不等于应用视觉完成。每次迁移一个页面，都要同时记录**目标、实现文件、截图、操作检查和剩余差距**；不能仅凭 `flutter analyze` 或空数据首帧声称与旧版对等。

## 落地顺序

| 阶段 | 实现内容 | 完成门槛 |
| --- | --- | --- |
| 1. Token 与主题 | `ThemeData`、`ColorScheme`、`TextTheme`、语义扩展、石墨浅/深色与系统跟随 | 与参考图的浅石墨/青绿方向一致；组件 Gallery 的颜色/文字/焦点通过对比度与大字体检查 |
| 2. 框架与基础组件 | 侧栏、页头、工具栏、按钮、卡片、空/错/加载态、统一业务弹窗 | 900×620 无溢出；键盘焦点和 Escape 路径完整 |
| 3. 任务与蓝图 | 系列卡、筛选、只读详情、任务蓝图/独立蓝图卡及画布 | 混合状态数据的浅/深色截图与旧版参考逐项对照 |
| 4. 其余页面 | 今日、四象限、日历、分类、纪念日、已处理、日报、设置 | 今日空态先按用户参考图验收；每页覆盖空、常态、错误、长内容与窄窗口 |
| 5. 桌面表面 | 菜单栏、小组件、系统授权/文件选择/更新提示 | 主窗口和原生表面的状态、名称与操作一致 |

业务规则、JSON 格式和原生桥接不因为换视觉而另起一套数据。`WorkspaceViewModel` 输出状态，组件只呈现及回传意图。新组件仅在两处以上真正复用时抽出；任务系列、日历块、蓝图节点保持业务组件，不强制塞进万能卡片。

## 每页验收矩阵

| 维度 | 必测组合 | 判定 |
| --- | --- | --- |
| 外观 | 浅色、深色、跟随系统切换 | 所有文字可读；边框、焦点、状态保持层级 |
| 尺寸 | 900×620、1200×800、1600×1000 | 无 RenderFlex 溢出、截断操作或不可达底部按钮 |
| 内容 | 空数据、普通数据、30+ 字中文标题、100+ 字说明、混合状态 | 计数正确；必要处可打开全文；空态与错误态不同 |
| 文字 | 1.0、1.25、1.5 倍文字 | 标题、表单和弹窗可滚动；主操作仍可用 |
| 键盘 | Tab/Shift+Tab、Enter/Space、Escape、Cmd+N、Cmd+K、Cmd+, | 焦点顺序可预测；菜单与按钮调用同一动作 |
| 辅助功能 | VoiceOver、系统高对比度、Reduce Motion | 图标有名称；状态有文字；无强制位移动画 |
| 状态 | idle、hover、focus、disabled、loading、success、error | 反馈清楚；失败不丢输入；loading 不重复提交 |
| 数据一致性 | 同一任务在今日/事项/四象限/蓝图/日历中更新 | ID、完成状态、日期、依赖与进度一致 |

截图数据需包含：独立任务、三层父子任务、一个阻塞子项、一项进行中、一项完成、一项取消、跨象限子任务、带阶段和里程碑的蓝图、临近及农历纪念日、系统日历事件、日报草稿。截图文件使用页面/外观/尺寸/状态命名，保存在不提交的验收目录或经评审后加入文档；不要用真实密钥、联系人或私人日历内容。

## Flutter 验证方式

1. `fvm flutter analyze`、相关 widget/业务测试，再运行全套测试。
2. `zsh scripts/build-app.sh` 并打开 `dist/序.app`，实际点击关键操作；CI 截图不能代替真实首帧与窗口检查。
3. 在 macOS 上检查浅深色、窗口缩放、长中文、键盘、VoiceOver、Reduce Motion；首先对照[用户提供的今日参考图](references/today-stone-reference.png)，再对照旧版 [事项 V3](../mockups/tasks-macos-v3.md)、[今日其他状态](../mockups/today-macos-redesign-v3.md)、[分类 V2](../mockups/categories-macos-v2.md)。
4. 检查 Flutter diagnostics 中无溢出、异常、重复提交和丢焦点。截图差异要说明是设计调整还是待修缺口。

推荐为纯组件建立 Gallery 和视觉回归样例，为业务状态建立 widget test；测试要验证用户可见结果，不只重复组件实现。系统菜单、通知、钥匙串、日历授权与公证等必须在真实 macOS 环境验证。

**今日参考图专项检查。** 标题栏采用全尺寸透明内容区，侧栏与顶部栏背景延伸到窗口顶端。侧栏品牌区避开系统窗口按钮。顶部栏显示位置、搜索与快速操作，侧栏包含两组导航和底部设置。标题区保留日期、标题与分隔线。空态图标、主句、说明、单一实心按钮与 `⌘ N` 提示依次居中。

## 当前 Flutter 差距清单（2026-11-09）

| 范围 | 当前代码观察 | 采用规范时的处理 |
| --- | --- | --- |
| 主题 | `XuTheme` 已接入石墨浅/深色、系统字体及基础卡片样式；输入、弹窗与复杂状态仍有页面级差异 | 逐页统一输入、状态色及高对比度表现 |
| 今日 | 日期、标题、分隔线、空态说明与添加入口已接入；空态图标仍使用 Flutter 内置日出图标 | 对照旧版核对有任务、纪念日和窄窗口状态 |
| 控件 | 页面直接使用大量 `Card`、`ListTile`、`AlertDialog` | 先统一基础状态，再逐页迁移；保留原生系统确认 |
| 事项 | 已有范围筛选和默认收起系列，但旧版筛选上下文、详情、卡片密度尚未完整对等 | 以混合数据截图与交互矩阵逐项修正 |
| 蓝图 | 已有卡片和画布入口，但卡片信息与旧版规划界面仍需比对 | 补状态、截止、阶段及键盘等效路径 |
| 其他页面 | 页面之间的空态、错误反馈、弹窗尺寸仍不统一 | 按页面清单依次纳入同一 token/组件规则 |

这份差距清单会随代码迁移更新；功能完成情况仍以[Flutter 迁移进度](../../FLUTTER-MIGRATION.md)和实际测试为准。
