## 生成方式与最终提示约束

使用内置 ImageGen，三个独立调用。原始生成文件保留于 Codex 生成目录，交付副本位于本目录。以下是最终提示的结构化摘要。

- **共同约束：** `ui-mockup`；目标1440×1024；中文原生 macOS；暖白／深青／石墨、SF／苹方系统字体、原有侧栏与导航；正文可读；无大统计卡、装饰、设备边框、无关 AI 按钮。所有图使用同一组任务、进度与日期；状态通过文字和图标表达。
- **周稿提示：** 以初稿周视图为参考，新增全部／待安排切换与两组可展开系列树；父任务显示1/4和截止；四个子项逐一标明时间／日期状态。上方系列范围从上周延续至周五，注明概览不占时段；周一、周三、周二分别出现界面设计、联调验证、阅读章节；周五发布检查只在当天待定时区。
- **月稿提示：** 以初稿月视图和本轮周稿为参考；自然月日期准确；19日选中且标今天；新版发布准备范围在16—18日、19—23日两段跨周连续；月格出现对应子项，23日截止另列旗标；右侧展示今天1项子任务、全系列1/4和后续子项日期，系统例会分开列。
- **日稿提示：** 以本轮周稿与初稿日历风格为参考；去掉遮罩与弹窗，呈现完整日工作台；系列树保留其他日期与待安排子项；时间轴滚动至13:00—19:00，14:00例会、15:00界面设计、16:00—18:00可用空档；全系列进度与今日子项数量分开；不伪造未定时任务的起止时间。

## 评审重点

1. 是否能一眼看清主任务与子任务的归属，以及系列全局进度？
2. 同一个系列跨日、跨周时，范围条与具体执行时间是否容易区分？
3. 「已定时」「已有日期、待定时」「待安排日期」三种状态是否清楚？
4. 日视图保留系列全貌、月视图按所选日期查看子项，信息密度是否合适？
5. 进入可交互原型后，再核对深层嵌套、多系列密集重叠、长中文、浅深色、大字号与无障碍操作。
