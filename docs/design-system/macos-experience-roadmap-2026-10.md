# macOS 体验与信息架构优化技术方案

日期：2026-10-20。状态：分析基线，部分范围已实施；以下“源码核实的现状”保留实施前证据，最新进度见文末。本方案逐项对应本轮 20 个问题，不涉及 iOS 专项工作。

## 核心判断

本轮不能只逐个改按钮样式。需要先解决五个概念的边界：**项目承载目标，任务系列承载拆解，任务承载行动，分类承载领域，蓝图承载可视化规划**。创建表单只负责捕获与安排，类别和项目的生命周期管理回到各自管理页面。

当前已有可复用的任务树、投影、依赖校验、统一弹窗和主题系统。建议保留这些基础，按批次调整，不引入平行任务数据库或第三方 UI 框架。

## 一、项目、系列与蓝图（对应 1、5、19）

### 推荐的产品定义

| 概念 | 定义 | 示例 | 是否直接排进一天/计算执行时长 |
| --- | --- | --- | --- |
| 分类 | 稳定的生活/工作领域，跨项目组织事项 | 工作、学习、家庭 | 否 |
| 项目 | 有目标、生命周期和可选目标日期的长期容器 | 序 1.0 发布 | 否 |
| 任务系列 | 为完成一个结果而组织的一棵任务树，可嵌套 | 改版添加事项流程 | 汇总容器不占时间；其可执行任务占时间 |
| 普通任务 | 可安排、执行、完成的具体行动 | 调整排期选择控件 | 是 |
| 蓝图 | 针对项目或任务系列的完整规划视图 | 拆解结构、执行依赖、进度 | 是视图，不复制任务 |

例如项目“序 1.0 发布”下面可以有“重做添加流程”“完善日报”“准备发布”三个系列，每个系列包含具体任务。“序 1.0 发布”标题不是再额外算一次工作量的任务。无需每创建一个系列就创建一个项目；允许独立系列和无项目任务。

### 系列需要显式区分，但不新增一套任务实体

第一批先在展示层区分“独立事项”和“任务系列”，列表汇总改为“X 个系列 · Y 项独立事项”，避免所有 Group 都叫系列。沿用同一个 `TaskItem` ID 与 `parentTaskID`，这是无模型改动的改良。

第二批建议给 `TaskItem` 增加可选 `kind`（`action` / `series`）。新数据明确类型；旧数据缺失时依据**完整任务集合**推导，不能因当前筛选隐藏了子任务就把系列变成普通任务。新增第一条子任务时，普通任务转为系列；删除最后一条子任务后保留空系列，只有用户明确转换时才变回普通任务。

系列根展示目标、子项进度和目标日期，不显示普通任务的开始执行/时长输入，不生成自己的日历时间块。任务数、日容量、日报完成数按可执行任务计算；系列总数单列，避免根与子项重复计量。系列进度从可执行后代推导，取消项单独报告、不冒充完成；无可执行后代显示“待拆解”，不显示 100%。父子线仍不代表执行依赖。

转换为系列时，已有日期、时间块、时长和完成历史要先预览影响，不能静默删除；可建议生成一项承接原执行信息的子任务。系列恢复为普通任务只允许在没有子项时进行。首期不顺带引入多父归属。

### 项目归属的技术收敛

不同时建立“新项目表”“旧蓝图容器”“自由项目文本”三套权威来源。现有 `BlueprintItem` 已具备名称、目标、日期、状态、阶段等项目元数据，可先用 `ProjectRef` / `ProjectRepository` 门面暴露为项目。暂时保留 `blueprintID` 与旧表名作为兼容存储，用户界面逐步采用“所属项目”；这需要连同项目管理与旧蓝图说明一起改，不能只重命名一个字段。

- 普通创建：“所属项目”可选，原生选择已有项目，默认无项目。项目创建、重命名、归档集中在项目管理页。
- 从项目内创建：继承项目 ID，显示上下文；从父任务内创建：继承父任务的项目归属，不允许子项悄悄归属另一项目。
- 未关联 ID 的历史 `TaskItem.project` 文本保留为“历史项目名”；提供显式映射，不能只因同名就自动合并到一个项目。
- 已关联项目 ID 的记录用该 ID 作为分组身份，名称只用于显示；项目改名不分裂日报。历史报告文本不回写，新报告保存当次名称快照。
- 旧阶段、里程碑、依赖与现有 ID 保留；依赖原本限制同一 `blueprintID`，在门面阶段仍保持该边界，不能为了去掉蓝图字段顺手解除校验。

### 蓝图升级为主窗口工作区

建议将“蓝图”恢复为工作区一级入口；项目/系列点击“查看蓝图”也进入同一主窗口详情区域。工作区内部提供目标选择、画布、按需检查器；面包屑显示“蓝图 > 项目/系列”。保留返回来源、筛选、滚动位置、当前节点、缩放与折叠状态。主窗口路由负责展示，不再通过弹窗退出通知决定导航。

建议引入带类型的 `WorkspaceRoute`（普通页面、项目蓝图、系列蓝图），`BlueprintNavigationState` 只存视图状态；列表、四象限、画布复用原任务 ID。`TaskBlueprintView` 与旧 `BlueprintDetailView` 的内容从 `@AppDismiss` 中解耦，返回由宿主路由处理。编辑节点、选择依赖等短流程仍使用 `appDialog`，蓝图本身成为全页面。

这是按用户“蓝图不要弹窗”的明确要求调整呈现职责；不需要推翻其他业务弹窗统一规范。实施时同步修订组件文档，明确工作区页面不属于短流程弹窗。

## 二、创建与编辑流程（对应 2～9、17）

### 统一表单结构

建议首屏顺序：名称 → 分类与项目上下文 → 安排 → 子任务（按需展开）→ 备注 → 更多设置。高级设置只保留象限、预计时长、截止时间，以及确有项目上下文的阶段/里程碑/依赖。日报章节不应要求每条任务创建时做一次决策，先保留旧值兼容，后续由报告模板映射。

| 编号 | 推荐交互 | 技术处理与验收 |
| --- | --- | --- |
| 2 | 添加与编辑只选已有分类，不出现“输入新类别” | 将所有 macOS 任务表单统一为 `TaskCategoryField(allowsCustomInput: false)`；搜索仅筛选，不隐式创建。无类别时显示“前往分类管理”而不是文本创建框。切换管理页面前保留草稿并明确返回；第一批可先用说明引导，避免丢草稿 |
| 3 | “安排”用三种语义：今天、明天、指定日期；“暂不安排”单独表达收集箱 | 用原生 `Picker(.segmented)` 表达互斥日期快捷项，指定日期时展开原生 DatePicker；“暂不安排（收集箱）”是无日期选择，不是第四个日期。先以 `TaskScheduleDraft` 适配现有持久化，不在纯样式批次重写状态模型。切换无日期后隐藏日期锁，保留草稿日期便于切回；已完成录入仍显示完成日期，不混入排期控件 |
| 4 | 删除通用创建表单的“关联已有蓝图” | 移除该 Picker；从上下文继承旧 `blueprintID`，项目归属由前述项目选择器负责。若已有项目阶段等，显示为上下文规划信息；不能通过删掉赋值导致原有继承丢失 |
| 5 | “所属项目”从自由文本变为已有项目选择 | 以 `ProjectRef` 收敛，独立任务允许无项目；历史自由文本显示兼容标签。不得把分类当项目，也不能因任务标题相似自动建项目 |
| 6 | 更多设置中的标签、值、说明分别使用统一字号角色 | 主字段和值使用 body/control，说明用 metadata；取消父 VStack 一刀切 `.font(.subheadline)` 的小字继承。先完成字体 resolver 再迁移，而非每个字段独立设大小 |
| 7 | 备注独立分区，持续可见的“备注”标签，多行输入和占位说明 | 复用原生 TextEditor/垂直 TextField，统一表面、边界、内边距和焦点；默认约 3 行可增长，长内容滚动；Tab/Enter 保持原生输入语义，不能把输入换行误作提交。创建与编辑使用同一 NotesEditor 业务组件并提供 Preview |
| 8 | 将“锁定计划日期”改为“固定安排”，附解释 | 解释为“批量调整与 AI 重规划跳过此项；如需修改，先解锁或明确确认”。不仅是改文字；统一入口规则，见下节 |
| 9 | AI 图片入口用带图标的次要 AppButton，已选后显示附件行 | 未选：选择图片；已选：缩略图、文件名、更换、移除；有效点击区域至少 36pt，移除也有名称。加载期间禁重复提交，错误在附件旁。保留当前压缩、大小限制、原生文件选择和发送范围说明，不伪造拖拽上传能力 |
| 17 | 主操作始终可以“添加”，查看蓝图是可选后续动作 | 用 `SaveDisposition`（关闭/继续添加/打开蓝图）与 `TaskCreationResult`（根 ID、子 ID、项目 ID）取代靠子任务数自动导航。普通“添加”保存后留在原页面，可通过成功反馈进入蓝图；用户明确选择“添加并打开蓝图”才导航。连续添加保持焦点，不积压退出后跳转；完成记录默认不跳蓝图 |

AI 与普通输入共享同一创建草稿模型和保存函数，AI 只填入待确认草稿，不直接生成项目、分类或持久化任务。图片按钮视觉优化不扩大 AI 数据发送范围。

### “固定安排”应当约束什么

当前 `planLocked` 并不是“任务不可编辑”，也不是“锁住截止日期”：它主要影响自动重规划和日历安排，但并不覆盖所有直接改期方法。拟统一为：

| 操作 | 固定安排的建议行为 |
| --- | --- |
| AI 重规划、批量平移系列、批量延期 | 跳过，结果预览列出原因 |
| 手工拖日历、点击“明天”、直接编辑计划日期/时间块 | 显示“解锁并修改”的明确确认；未确认则不落盘 |
| 编辑名称、备注、分类、执行状态 | 允许，固定安排不等于锁住任务 |
| 修改截止时间 | 允许；截止与计划是不同属性，仍做日期/依赖校验 |
| 系列汇总容器 | 不显示任务级日期锁；系列批量移动逐项跳过固定的可执行子项 |

将校验下沉到 `TaskSchedulingPolicy` / 统一安排命令，携带操作来源（手工、批量、AI），不能只依赖按钮 disabled。手工确认后执行一次受控修改，锁是否继续保持由界面明确提示，建议保持“新安排仍固定”。

## 三、点击区域与日历入口（对应 10、12、20）

- **10：右上角主题菜单。** 当前搜索按钮已有 40pt 区域，主题 Menu 标签没有相同约束。扩大整个“图标+主题名”的标签为最小 40pt 高，使用统一命中区域 token 和 `contentShape(Rectangle())`，不要只放大调色盘图形。若用户实际指的是列表/四象限样式切换，也纳入本批：每段最小高度 32～36pt、可见状态和键盘操作一致。两处都验收，避免只改错入口。
- **12：日历重复添加。** 当前顶栏存在“安排事项”，右侧任务系列标题存在加号，两者都执行同一个 `onAddTask`。按请求移除任务系列标题右侧加号，保留顶部唯一创建入口；“从已有任务安排时间”使用另一个明确动作，不能让名为“安排”的按钮实际只创建。侧栏隐藏/显示时创建入口始终可达。
- **20：系列展开按钮。** 当前事项页箭头仅 16pt 宽、36pt 高，日历系列箭头还缺少明确 frame。两者统一为最小 36×36pt、重要侧栏可用 40×40pt。箭头图形维持紧凑，热区覆盖空白；不要把完成勾选或更多菜单的点击也拦截为展开。支持 Left/Right 收起/展开并朗读展开状态。相同策略检查蓝图树与筛选后的上下文父行。

这些尺寸是拟定的应用命中区域标准，不声称是 Apple 针对所有桌面控件的硬性数值。纯视觉大小与交互热区分开管理。

## 四、分类重构（对应 11，并支撑 2、14）

“大调整”建议重点改变职责和数据身份，而非再次换一套配色。

1. 分类固定为**单层、单选领域**，例如工作/学习/生活；项目不放入分类树。暂不增加多标签与多级类别，避免与任务树形成两套层级。
2. 分类 Tab 成为唯一管理中心：类别导航、类别详情/编辑、所属任务预览，管理“名称、图标、排序、归档、合并”。任务预览按项目/系列分组，复用 `TaskSeriesProjection`，不要在分类页重复实现一套树规则。
3. 内置“所有类别/未分类”与用户类别区分；导航计数继续采用全部状态记录数并写清口径。系列数与可执行事项数分别显示，归档类别不会隐藏其未完成任务或破坏“所有事项”。
4. 新增稳定 `CategoryRecord.id`，任务可选 `categoryID`，保留旧 `category` 名称作为兼容快照。图标从本机名称键迁移到类别 ID 元数据；旧名称按既有大小写/空格归一规则建立一次映射，不能在每次渲染时猜关联。
5. 重命名不再作为任务身份变更；归档保留引用，新的选择器默认隐藏已归档项，但已有任务仍显示其完整名称；移除/合并先预览影响并一次提交，源类别最后归档，避免半迁移。
6. 图标库继续使用现有 55 个符号和共享选择器；搜索从“创建入口”彻底改为“选择已有”。不要为管理功能另做多个类别输入组件。

建议先落地“选择入口统一”和预览分组，再做 ID/归档/合并的数据迁移。不能把稳定 ID、备份兼容和归档当成本轮已经完成的能力。

## 五、记录页空状态（对应 13）

复用 `AppEmptyState`，增加必要的页面布局配置（容器内/整页、可选操作），统一页头、留白、图标尺度、说明宽度与按钮位置。内容文案仍按业务区分，不把所有空态都写成“暂无数据”。无数据、筛选无结果、加载失败分开。

| 页面 | 初次空状态 | 主要操作 | 筛选空结果 |
| --- | --- | --- | --- |
| 收集箱 | “收集箱里还没有事项”，不能在从未使用时声称“已清空” | “收集事项”，预填暂不安排 | 清除筛选 |
| 纪念日 | “记录一个重要日子” | 新建纪念日 | 清除类型/日期筛选 |
| 已处理 | “还没有已处理的事项” | 可无按钮，保留说明 | 清除状态/日期筛选 |
| 日报与复盘 | “记录今天的进展” | 生成日报，模板可用 | 清除期间/类型筛选 |

同一状态只出现一个主要创建入口：整页空态可把页头主按钮移到主体，已有内容或仅筛选无结果时保留页头，不再叠加第二个按钮。错误态保留真实错误与重试，不冒充空态。

## 六、日报模板与复盘（对应 14～16）

### 模板与“今日关联分类”

模板是独立的报告配置，不是任务分类。建议内置“工作进展”“按分类汇总”“个人回顾”三种，用户可复制后编辑章节、分组方式、字数和默认类别范围。现有固定三段作为一个内置兼容模板，不强制所有人迁移输出格式。

`ReportTemplate` 建议包含稳定 ID、名称、版本、章节定义、分组方式（项目/分类/系列）、类别范围策略和字数；历史报告保存模板版本、当次配置、来源任务 ID 与显示快照。更改模板不改写已保存日报。

生成前显式显示日期和候选类别：从当天候选任务推导非空类别，支持多选，未分类单列；“全部类别”与“未选任何类别”是不同状态，不能把空选择意外解释为发送全部。切换类别立即更新任务预览和数量，自动生成只读取已确认集合。按类别筛选时不把父任务上下文再次计为完成记录。

当天候选集合可先沿用“今日安排 ∪ 当日完成 ∪ 当日处理”，按 ID 去重，但区分“计划”“实际完成”“取消/延期”。明日规划单独读取明日安排与明确选择的未完成项，不能直接把所有今日未完成宣称为明日已安排。没有任务但有用户补充时仍可生成；没有任何输入则提示选择范围或补充内容。

建议抽出 `ReportRequest`（日期区间、模板版本、类别选择、来源 ID、补充、字数、允许发送字段）与 `ReportSourceBuilder`。当前报告 prompt 会带入备注/阻塞说明，新的报告链必须显式遵循 AI 备注/项目发送偏好，并在生成前用同一 DTO 做预览与发包；不要只在预览隐藏、请求仍发送。

### 生成日报弹窗

继续使用统一 `appDialog`，采用“来源与配置 → 可编辑结果”的分区结构。宽窗口可双栏，窄窗口按步骤排列；固定底部动作，正文区域允许增长/滚动，不再用固定 760×720 容纳一切。

- 配置区：报告日期、模板、类别范围、来源预览、补充说明；字数放入次要选项。
- 结果区：未生成时显示真实来源摘要；生成中显示进度与可取消状态；失败就地错误/重试并保留已有正文；成功展示可编辑 Markdown 和字数。
- 主动作随状态变化：生成 → 重新生成 / 保存；重新生成有手动修改时先确认替换，旧正文不因请求开始而被清空。
- 保存采用草稿 ID 与内容修订版本，编辑后恢复“待保存”；避免当前 `isSaved` 布尔值在文本继续变化后仍禁用保存。
- 网络任务用 request ID / cancellation，关闭后迟到结果不能写到下一份报告；空态不承载错误提示；未保存退出使用 `onAppDialogCancel`。

### 周、月、年复盘

用统一 `ReviewPeriod`（week/month/year）与期间选择器，默认本周、本月、本年，显示确切起止日期；周起点尊重用户日历设置。使用 `Calendar.dateInterval` 产生 `[start, end)` 边界，不用“天数×86400”计算月份/年份，也不只写 `>= start`。

新增通用 `ReviewItem` / SwiftData 记录，保存期间类型、起止、时区、总结、下一期间重点、来源快照。旧 `WeeklyReviewItem` 一次导入为 week 类型并保留原 ID；导入标记避免重复，同时让旧备份仍可读取。列表按期间筛选和查看历史，而不只展示最近四条周复盘。

月/年复盘不能直接扩大当前周查询：当前任务只保留当前状态及少量时间戳，无法完整还原每次完成、恢复、延期。首期应明确“按现存完成记录统计”，不伪造历史；如需准确期间趋势，增加 `TaskActivityEvent`，以后追加完成/恢复/取消/改期等事件及必要快照。历史数据不反向编造事件，缺失区间标为不可用；事件的统计语义需处理恢复与再次完成，不能直接按事件条数当完成任务数。

## 七、字体系统整顿（对应 6、18，也影响全部页面）

已完成工作区只读检索，结果见 [字体审计](typography-audit-2026-10.md)：432 处 font 调用、22 处直接数字字号、8 处数字小于 13pt，另有 122 处直接的小字号语义角色。**最大问题还在 token 映射**：本机 `.caption1` 只有 10pt，所以包括新分类页面在内的 token 页面也需要审查。

建议在 `AppTypography` 内新增面向应用内容的 `AppTextRole`，定义字体角色、基础字号、字重和可读下限。页面只选角色，不接受任意数字。原生菜单、系统对话框保持系统行为，不用业务字体覆盖全部原生控件。

| 应用角色 | 建议 100% 基础字号 | 用途 |
| --- | ---: | --- |
| pageTitle | 28pt | 页面主标题 |
| sectionTitle | 20pt | 内容分区、弹窗标题 |
| taskTitle | 15pt | 任务名称、系列标题 |
| body / formValue | 14pt | 正文、输入值、备注、日报正文 |
| control / fieldLabel | 13～14pt（落地时各角色固定一种） | 操作、字段标签 |
| metadata / helper | 12pt | 日期、状态、操作解释 |
| canvasLabel | 12pt | 默认画布节点辅助文字 |

这些是产品提案值，不是宣称现有规范已经规定这些尺寸。需要在 Gallery 的纸张/石墨/墨色、100%/125%/150% 字号下确认后更新 foundations/components。由一个 resolver 应用用户字体设计、缩放和最小可读值；密度只调间距，不能悄悄把正文缩回 10pt。画布缩放属于几何视图缩放，默认/适配视图需保持主要标签可读，极低缩放采用信息简化而非塞更多小字。

迁移顺序：添加表单和高级设置 → 日报/复盘 → 主题工具区 → 蓝图/项目 → 分类/日历/记录页 → 剩余设置与辅助页面。不能只修 8 处数字字号；还要检查直接 `.caption`、`font(.caption1)`、`AppTypography.caption` 及父容器继承。

新增静态审计限制业务页继续增加数字字号，例外进入明确白名单。验收包含长中文、换行、行高、按钮随字增长、焦点和读屏，不能只看截图里的字号数值。

## 八、数据兼容与实施顺序

### 兼容边界

- 第一批纯 UI 调整不改模型，不启动不必要的数据迁移。
- 稳定类别 ID、显式系列类型、报告模板与通用复盘按数据批次增加可选/可缺省字段；旧字段在兼容期保留，所有新字段使用明确缺省解码。不能假定 Swift 属性默认值自动解决旧 Codable 缺字段问题。
- `WorkspaceSnapshot.isValid` 目前只接受 `formatVersion == 1`；升级导出格式时必须同步导入、验证、文件夹同步和冲突处理，支持读入 v1，生成迁移预览及迁移前备份。旧客户端不认识 v2 时给出明确提示，不能宣称可无损双向同步。
- SwiftData 记录、内存模型、备份 DTO 与同步 DTO 一起检查；迁移按事务提交，稳定 ID 不因重命名变化，失败保留原数据与回滚路径。类别合并、项目映射不能边遍历边触发多次独立持久化。
- 旧蓝图的 ID、阶段、里程碑、依赖、归档和工作流画布信息不因改称项目而丢失。计划锁策略迁移不改既有布尔字段，但必须统一操作验证。

### 建议批次

| 批次 | 覆盖编号 | 主要交付与依赖 |
| --- | --- | --- |
| A：表单与基础可读性 | 2、3、4、6、7、9、10、12、13、17、18、20 | 先确认文字角色与控件状态，改创建/编辑表单、日期快捷项、备注/附件、点击热区、重复操作与空态；默认添加不跳蓝图；不做项目数据迁移 |
| B：蓝图工作区 | 19，承接 1、17 | 主窗口 typed route、来源恢复、全页面蓝图，去除蓝图对弹窗关闭的依赖；保留现有任务/旧蓝图读取与节点编辑 |
| C：领域与安排规则 | 1、5、8、11 | 确认项目/系列/分类定义后，实施 ProjectRef、显式系列、稳定类别 ID、分类管理与统一锁策略；联动全部计数与排期校验，不只改页面 |
| D：报告与复盘 | 14、15、16 | 模板、当日类别范围、来源 DTO、可编辑结果、周/月/年期间与历史兼容；精确历史趋势另外依赖活动事件 |

不建议按编号顺序做 20 个独立补丁。A 批能先解决使用阻力；B/C 决定后续数据语义；D 基于稳定的分类、项目和计数规则再扩展。

### 每批验收

1. 普通任务、独立系列、项目内系列、历史蓝图、跨类别子任务、受阻/取消/空系列都有明确展示与计数，不复制任务。
2. 创建只选已有分类；添加/添加并进入蓝图/连续添加行为独立；从管理页返回不丢草稿。
3. 日期快捷项、未安排、固定安排、截止时间区分；任何自动或批量操作跳过固定项，手工改期明确确认。
4. 所有创建与选择短流程走统一 appDialog，蓝图为主窗口页面；返回与关闭恢复合理焦点。
5. 记录页空态、筛选无结果、网络失败不同；同一状态一个主创建入口。
6. 报告预览与发包来源一致、类别选择可见、AI 发送偏好生效、无重复来源；周/月/年区间含跨年与夏令时边界用例。
7. UI 在浅深色、长中文、字号放大、Reduce Motion、键盘与 VoiceOver 下验收；点击热区不相互覆盖。
8. 数据批次验证 v1 备份读入、v2 导出/导入、同步冲突、ID 保留与事务失败回滚；只读 UI 批次不增无关模型迁移。
9. 每次代码批次都运行针对性测试，生成并打开 `dist/序.app`；迁移记录写真实结果，不用设计稿截图冒充运行效果。

## 需要在实施前确认的产品判断

本方案的推荐基线是：分类为单层单选领域；项目为独立目标容器；系列根是汇总而非另一项可执行工作；蓝图进入主窗口一级工作区。它们是建议，不是已经被本轮代码实现或既有数据保证的事实。

若希望分类同时承担多标签、客户/项目树，或希望系列根本身也能计时执行，应先调整上述定义和统计口径，再做模型迁移。纯样式、只选已有分类、取消强制蓝图跳转等改进不必等待全部长期数据方案才能开始。

## 2026-10-20 实施进度

本轮已落地：添加与编辑只选已有类别；日期快捷项与收集箱独立呈现；通用添加表单移除“关联已有蓝图”并改为现有项目选择；备注共用多行样式；固定安排说明及直接改期拦截；AI 图片次要按钮；主题和系列箭头热区；日历重复创建入口移除；四类记录页空态对齐；普通添加与可选打开蓝图分开；任务与项目蓝图进入主窗口；日报三种内置模板、今日分类范围、来源去重、AI 发送偏好和可编辑保存；周/月/年复盘。`AppTypography` 设立 macOS 文字最低基准，并迁移直接小字号角色调用。分类任务预览已按系列分组。
