# Design System 渐进迁移记录

本记录只追踪已迁移的呈现层。已确认的规范见 [README](README.md)、[设计基础](foundations.md) 和 [组件规范](components.md)；审计时的旧状态保留在 [ui-audit.md](ui-audit.md)。每批先核对空态、有数据状态和操作入口，再分别编译 macOS 与 iOS 目标。任务筛选、持久化、API、备份格式和状态变更调用不因视觉迁移而改变。

## 批次 1：今日试点

- macOS `TodayWorkbenchView`：标题、间距、圆角与边框接入 token，保留用户主题偏好与现有任务分组。
- iOS `IOSTodayView`：页面、卡片、标签、操作和空态使用 Design System，导航与表单保持系统控件。
- 原有构建与截图验证见 [试点记录](pilot.md)。

## 批次 2：收集箱、日历计划、已处理与 iOS 事项 sheet

| 范围 | 原有问题 | 本批组件与 token 映射 | 保留的行为 |
| --- | --- | --- | --- |
| macOS 收集箱 | 空态和页面边距由页面内数值定义 | `AppEmptyState`、`AppSpacing.section/x8` | 未安排任务筛选、时间倒序、`TaskCard` 选择 |
| macOS 日历计划 | 统计、日历事件和日期分组的颜色、间距、圆角各自定义 | 主题强调色、`AppColors.warning/textSecondary/border`、`AppTypography`、`AppSpacing`、`AppRadius.control`、`AppEmptyState` | 7/30 天范围、系统日历授权和刷新、任务分组及操作 |
| macOS 已处理 | 空列表复用了“今天还没有安排事项”的提示 | 独立 `AppEmptyState`、`AppSpacing.section/x8` | 已处理任务及原有时间排序、`TaskCard` 操作 |
| iOS 新增事项与详情 sheet | 文字样式和状态展示未完整映射 | `AppTypography.body`、`AppBadge` 语义状态、`AppEmptyState`；保留系统 `Form`、`Section` 与工具栏按钮 | 保存校验、任务状态操作、关闭行为 |

`TaskCard`、`PageHeader` 等现有业务组件仍由 macOS 主题偏好控制，本批不对它们做全局重写。该批完成时 iOS 主导航仍只有“今日”；新增事项和详情是该试点中的系统 sheet。

验证：macOS 14+ 应用通过 `scripts/build-app.sh`，已打开开发版并查看收集箱、日历计划、已处理的空态；iOS/iPadOS 17+ 目标通过 Xcode Simulator Debug 构建，已在 iPhone 16 Pro 模拟器查看新增事项和详情 sheet。详情状态的辅助功能文本核对为“状态、进行中”，没有重复朗读文案。`swift test` 的 32 项现有测试全部通过。iOS sheet 配有 Dark 和大字号 Preview 配置；完整 VoiceOver 朗读、最大字体尺寸和有数据的系统日历页面仍需后续人工走查。

## 后续顺序

后续优先按「日报与复盘」→「蓝图」逐页迁移；每页先记录其空态、主操作与主题差异。工作流画布、设置窗口和小组件的交互复杂度较高，单独验收键盘、焦点与辅助技术路径。iOS 已因“今日”和“分类”两个一级页面启用系统 Tab Bar；iPad 的更宽布局后续可评估 `NavigationSplitView`。

## 按钮规范修订

针对页面按钮显得厚重、桌面分段按钮与其他按钮尺寸不一致的问题，`AppButton` 改为明确的三级视觉尺寸及独立点击区域，统一图文间距、圆角、浅底次要样式、按下/禁用/加载反馈。macOS `AddTaskControl` 缩至 34pt 可见高度并补齐菜单分隔和可见下拉箭头，`TaskCard` 与「分类」页图标操作扩大到 36×36pt；「今日」重点操作、空态操作、辅助操作、页面标题操作、日报入口及分类页新建任务接入统一按钮。iOS「今日」重点卡片及空态自动使用新样式；导航栏和表单操作仍为系统按钮。浅色大字号与深色常规尺寸已在模拟器核对，桌面开发版已查看并实际打开下拉菜单。

## 批次 3：分类页面设计稿落地

- macOS `TaskCategoriesView` 按[分类设计稿](mockups/categories-design.md)改为类别栏和任务区两栏。类别数、状态数来自真实任务数据；命名类别可重命名与删除，任务行保留完成、查看、改类、状态操作、日历、象限与删除入口。空态操作使用用户主题强调色。
- iOS 新增 `IOSCategoriesView`，以系统 Tab Bar 与“今日”并列。横向类别选择、原生分段筛选、类别管理、任务改类和预选当前类别的新建任务 sheet 共用 `TaskStore` 数据；iOS Asset Catalog 的品牌、页面、卡片和边界语义色更新为设计稿的浅/深色暖纸张配色，“今日”同步使用这组全局语义色。
- 两端页面均提供 SwiftUI Preview，任务数与空态从筛选结果计算；iOS 任务行及图标操作至少有 44pt 点击区域。任务模型、SwiftData、API 和备份结构未改。
- 验证：macOS `swift build` 与开发版 `.app` 构建成功，已在实际应用中检查空态和类别选择；现有 `swift test` 的 32 项测试通过。iPhone 16 Pro 模拟器构建成功并打开分类页，检查了导航、类别、筛选、任务行和新建入口。

### macOS 分类任务区视觉校正

状态筛选改用页面内的三段按钮，选中项使用当前主题强调色文字和浅色主题底，未选中项保留次要文字色；三段的高度、内边距和间隔共用 `AppSpacing`、`AppRadius`、`AppTypography`，VoiceOver 保留任务数与选中状态。任务行让标题和时间占据左侧剩余宽度，类别标签按内容宽度显示并限制长名称，更多操作固定在右端；标题用 `headline`、时间用 `caption`。分类页双栏、输入框和任务区边距沿用本批布局。macOS 开发版已构建并打开，使用两条现有任务核对任务行，实际切换待处理、已处理、全部三个状态，并查看了纸张与墨色两种外观；检查后恢复纸张主题。

对照原始设计稿再次校正：状态筛选移除整体底板，仅选中项保留浅色主题底；任务行的勾选框使用 18pt 可见方框和独立点击区域，标题、时间与类别标签的间距按设计稿收紧，日期在今天或明天时使用相对称呼。Preview 扩充为四条不同类别的任务，便于检查设计稿中的完整列表密度；实际任务列表仍根据当前筛选展示全部结果。

任务行再按局部设计稿改为顶部对齐：28pt 宽的勾选操作区与标题之间仅留 4pt，类别标签和更多操作留 12pt 间隔；勾选操作区保持 44pt 高度。已重新构建并打开 macOS 开发版，在实际两条任务的列表中核对位置。

任务行的上下内边距从 20pt 收至 16pt；类别标签和更多按钮放入同一个 36pt 高的水平容器，以共同的垂直中心线对齐，保留更多按钮的 36pt 点击区域。已在开发版有数据页面核对。

## 批次 4：macOS 任务树添加与蓝图投影

- 普通任务与 AI 草稿共用子任务录入区：回车连续添加、直接编辑或移除同名草稿，保存前显示创建数量；连续添加保留焦点并提供“查看蓝图”。未保存内容关闭时给出放弃提醒。
- 主任务和子任务仍是 `TaskItem`，一次验证并写入同一任务集合；子任务以 `parentTaskID` 关联。没有子任务时仍是单项任务，不生成空蓝图。旧 SwiftData、JSON 备份和文件夹同步结构不变。
- “蓝图”页增加由未关联旧蓝图的任务树派生的卡片，进入后可切换蓝图、列表、四象限，三个视图都读取相同任务 ID。旧 `BlueprintItem` 保留；在旧蓝图内新增的任务树显示父子虚线和主任务焦点，不生成重复卡片。父子线只用于结构与布局，执行阻塞仍只看 `dependencyIDs`。
- 通用任务列表在同一筛选结果包含父子项时可展开和收起子项；四象限继续按每项任务自己的象限呈现。主任务显示子任务完成进度，完成子任务不会自动完成主任务。
- 验证：`swift test` 共 35 项通过，含任务树一次保存、视图 ID 一致、独立象限、旧蓝图不重复和父子非依赖测试；macOS 开发版通过 `scripts/build-app.sh` 并打开，在真实窗口检查快速子任务输入、回车后焦点、空子任务输入的 Escape 行为和放弃提醒；iOS/iPadOS 17+ Simulator Debug 构建通过（共用模型兼容）。

### 顶部操作精简

macOS 主窗口右上角移除重复的“添加事项”组合按钮；“今日行动”等页面内入口保留。`⌘N` 改由系统“文件”菜单触发添加事项。开发版已构建并打开，实际窗口确认顶部按钮消失、`⌘N` 仍打开添加窗口；iOS Simulator Debug 构建通过。

### macOS 临时弹层的点击外部关闭

搜索与快速操作由阻断主窗口的 sheet 改为锚定搜索按钮的原生 popover；蓝图页“从模板创建”“AI 变更记录”和画布中的“加入已有任务”同样使用 popover。点击弹层外的应用空白处或按 Escape 即关闭，搜索命令的导航行为保留。实际窗口已核对搜索、模板和变更记录的外部点击；新建、编辑和同步冲突等有未保存内容或明确决策的表单仍保持原生 sheet。

## 批次 5：macOS 事项工作区

- 工作区侧边栏改为「今日、事项、分类、日历计划」；收集箱、纪念日、已处理和日报仍留在「记录」。事项页以任务集合为主，使用原生分段选择列表或四象限，并提供待处理、全部、收集箱、已处理范围。四象限复用 `QuadrantPanel` 和现有 `TaskCard`，不新增任务模型。
- 旧蓝图库通过事项页的次级入口及既有快速操作保留；每项任务可从任务卡片菜单、今日行菜单或编辑窗口打开对应蓝图。独立任务直接成为单节点蓝图，可在视图中快速添加子任务；子任务会定位到所属任务树，已有旧蓝图关联的任务定位到旧工作流。
- 今日重点卡片下增加四象限数量概览。选择象限会筛选下方待处理事项，当前重点始终置顶；再次点击或「清除筛选」恢复全部。
- 布局使用现有 `AppSpacing`、`AppRadius`、`AppTypography` 和用户主题色。`TasksHubView` 提供 Preview，工作区与蓝图入口均有可读的辅助功能名称。
- 验证：`scripts/build-app.sh` 已成功生成开发版 `.app` 并打开；实际窗口检查了四个工作区入口、事项空态、列表/四象限切换和蓝图库返回路径；`swift test` 36 项通过，`git diff --check` 通过。本批仅调整 macOS 呈现层和任务树只读定位，不改任务持久化结构及 iOS 页面。
