## 现有逻辑与需要澄清的问题

| 主题 | 工作区实际行为 | 本次设计决策 |
| --- | --- | --- |
| 类别结构 | `categories: [String]`，任务 `category` 为可空名称；类别不是树 | 保留单层类别。页面层级指视觉信息层级，不引入父子类别、项目或第二套任务 |
| 所有类别 | 包含所有 `store.tasks` | 作为内置任务范围，不参与编辑、删除或图标定制 |
| 未分类 | `nil` 或去空白后为空 | 作为内置任务范围，固定托盘图标；删除类别后选中此范围 |
| 类别计数 | 每个类别的全部状态任务数 | 数字列标明“总数”，不随右侧状态切换跳动；页头同时显示总数与待处理数 |
| 待处理 | `needsAction`，包含受阻，排除已完成与已取消 | 沿用该定义；受阻行明确显示文字，不伪装为已处理 |
| 已处理 | `!needsAction`，包含已完成和已取消 | 保留总范围，但在每行区分“已完成”“已取消”并使用不同符号 |
| 排序 | 待处理按计划时间升序，未安排在后；其他范围按创建时间倒序 | 排序提示随范围变化，修正目前始终显示“按计划时间排序”的误导；不新增无对应逻辑的排序菜单 |
| 新增类别 | 去首尾空白、按名称不区分大小写去重 | 使用统一的类别编辑窗，可先输入名称再选图标；重复名称给就地提示，成功后选中新类别 |
| 重命名 | 同步修改该名称下所有任务 | 编辑窗里说明同步影响；内置范围无编辑入口 |
| 删除类别 | 所属任务 `category = nil`，保留任务本身 | 确认框展示受影响数量与去向，不把“删除类别”写成“删除任务” |
| 任务改类 | 只更新被选任务的类别 | 任务行更多菜单保留改类；不承诺自动级联父任务/子任务 |
| 新建任务 | 命名类别下预填该类别 | “所有类别”“未分类”下默认为未分类，正式实现仍打开现有创建窗 |

计数以任务记录为单位：子任务本身也是 `TaskItem`，按各自类别和状态计数，父任务上下文不额外生成一条记录。不因类别页面而改变任务树、依赖或蓝图语义。

## 视图与信息层级

1. **应用层**：保留原侧边栏、工作区面包屑和主题入口。设计图中非分类导航为静态外壳，不模拟其他页面。
2. **页面层**：标题“分类”加一句说明；右侧只保留一个“添加事项”主按钮，删除大写英文眉题与装饰线。
3. **类别层**：内置范围与“我的类别”分区；每行统一使用“图标、名称、总数”，用轻选中背景定位。以细分隔线组织导航与任务区，减少双重大卡片。
4. **内容层**：当前类别图标与名称、总数及待处理数；“编辑类别”作为低强调动作；下一层为状态筛选与真实排序提示。
5. **任务层**：标题优先，其下为日期、受阻原因、父任务上下文等；象限与更多操作次要。颜色之外保留文字、勾选和取消符号。

主视图不增加进度仪表盘、图标统计或无实际用途的辅助卡片。任务区继续以同一集合的筛选结果呈现。

## 图标库与编辑流程

**入口**：新建类别或“编辑类别” → 点击图标预览/“更换图标” → 图标库 → 选择 → “使用此图标” → 返回编辑草稿 → “保存更改”。图标库取消只撤销本次选图；编辑窗取消丢弃整份草稿。最近使用可在选图确认后更新，它不代表类别已经保存。

- 使用系统 SF Symbols。设计稿内嵌实际系统符号的透明图像，无网络字体或第三方图标依赖；正式 SwiftUI 使用 `Image(systemName:)`。
- 本稿提供 **55 个候选图标**，按工作、生活、学习、健康、兴趣、出行、财务分组，另有推荐与全部。全部候选已通过本机系统符号导出确认存在；正式落地仍需在最低支持 macOS 14 验证可用性。
- 推荐页同时显示最近使用与精选常用，降低反复搜索成本；正式应用的最近使用初始为空，无记录时隐藏此分区，不写入示例历史。
- 搜索跨全部分组，覆盖中文名称、关键词、英文 SF Symbol 标识；例如“书”能找到书本、书架与铅笔，不受当前分组限制。清除搜索恢复原分组。
- 点击图标后以边框与勾号共同表示选中，底部显示中文名与 SF Symbol 名称；“使用此图标”确认，避免浏览即落盘。
- 本轮不加入颜色编辑器：图标统一跟随当前主题强调色，类别识别依靠图形和名称，不再新增一组持久化颜色。
- 图标在类别导航、当前类别标题、任务类别选择器与改类菜单中保持一致。未知或已不可用图标回退为 `tag`；内置范围分别固定为 `square.stack` 与 `tray`。

图标选择器正式实现建议用原生 sheet 或现有可关闭弹层、`TextField`、`LazyVGrid` 与 `Button`；尺寸采用 4pt 间距、语义字号、`AppRadius`，无需抽象一套跨平台图标库 UI 框架。

## 空状态与操作归属

| 情况 | 主体说明与下一步 |
| --- | --- |
| 完全没有任务和自定义类别 | 显示“先从一个类别开始”及“新建类别”；仍允许左栏先新建。此评审状态隐藏任务主按钮以突出类别创建，属于待落地交互决策 |
| 某个类别没有任务 | 显示类别符号与“这个类别还没有事项”；沿用页头唯一“添加事项”，不在主体重复按钮 |
| 未分类为空 | “所有任务都已有归属”；说明新收集且未归类的事项会显示于此，不宣称全部任务已完成 |
| 类别有任务，待处理为零 | “这里的事项都已处理”，提供“查看已处理”；不显示首次使用文案 |
| 已处理筛选为零 | “还没有已处理的事项”，提供“查看待处理”；保留类别与状态上下文 |
| 图标搜索无结果 | 就地反馈无匹配并提示换关键词；底部已选图标保留，不清空有效选择 |
| 重名或空名称 | 编辑字段下就地错误，草稿与图标选择保留，不静默吞掉新增动作 |

编辑窗的“删除类别…”是低强调危险操作，进入独立确认，不与保存并列为主操作。所有类别与未分类不出现管理按钮。

## 图标数据落地边界（尚未实施）

现有任务类别是名称字符串，类别清单存于 `UserDefaults`，备份与文件夹同步另有类别数组；**当前仓库没有类别图标字段**。设计稿中的临时 ID 仅用于模拟交互，不能当作已完成的数据迁移。

建议首期保留 `TaskItem.category` 与类别清单原样，新增独立、可选的图标元数据映射：规范类别名 → 已知 SF Symbol 标识。没有元数据的旧类别统一回退 `tag`；重命名时同步迁移映射键，删除时清理映射。大小写、首尾空格与现有去重规则保持一致。不根据名称自动覆盖用户已选图标。

实现时再决定映射是否进入备份/同步：若仅存本地，则旧备份和同步数据格式不变，但换设备/恢复备份不能承诺保留图标；若要随备份恢复，应增加可选字段并验证旧文件缺失该字段时仍可读取。该决策需与用户目标一起确定，不能把设计稿当成已解决的持久化兼容方案。

## 组件映射与落地检查

| 设计元素 | SwiftUI 落地映射 |
| --- | --- |
| 添加事项 | 现有 `AppButton` prominent，主题 `AppPreferences` |
| 类别导航与筛选 | 原生 `Button` / `List`，保留选中语义；`AppSpacing` / `AppTypography.desktop` |
| 编辑、新建类别 | 原生 Form 与现有 sheet 关闭流程；原生确认/取消按钮 |
| 图标网格 | `LazyVGrid` + 原生 Button；文字辅助名称、选中 traits、键盘焦点 |
| 空状态 | 现有 `AppEmptyState` 或业务空态布局；不另封装通用卡片 |
| 错误与删除确认 | 行内错误文字 + 系统确认对话框 |
| 图标与分隔 | `Image(systemName:)`、语义前景色与 `AppColors.border` |

大窗口使用轻量双栏；窄窗口收起类别栏为原生范围选择/类别选择器，而不是把三列硬挤在一起。HTML 的窄屏折行为评审可读性处理，不代表 iOS 产品设计。保持 macOS 主题、密度、字号偏好；正式实现不能照抄 CSS 的像素值或颜色常量。

键盘路径需包括类别导航、筛选、搜索、网格选择、确认及 Escape；图标需有中文名称、选中读屏状态与可见焦点，长中文允许换行。减少动态效果时移除非必要进场；深色沿用同样信息结构。图标库内的预览图形始终有名称，不能只依靠颜色。

## 本轮验证

浏览器中检查浅/深色主页面、编辑窗、图标库、空类别、首次使用与已处理；验证名称与图标保存、重名提示、删除后任务保留、任务预填类别、新建任务与完成后计数更新，以及窄宽度无横向溢出。仅验证设计原型，不代表 SwiftUI、VoiceOver 或 macOS 14 真机验收。本轮未改应用源码，无需重建开发版 `.app`。
