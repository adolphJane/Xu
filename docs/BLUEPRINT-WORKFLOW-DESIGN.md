# 蓝图节点工作流设计方案

本文面向当前 Flutter macOS 主应用。第 1～6 节保留原工作流设计，其中的 SwiftUI 交互和类型名用于迁移对照。第 7～12 节定义蓝图编辑、编排和执行的首批需求。第 13～16 节在此基础上补充进度判断、计划调整、里程碑验收和模板复用。当前交付情况见[迁移进度中的蓝图工作区](FLUTTER-MIGRATION.md#蓝图工作区)。

## 1. 目标与范围

蓝图从“阶段、里程碑、任务列表”升级为可视化任务依赖图。用户应能快速回答：当前能做什么、某项任务为什么还不能做、完成后会解锁什么。参考图用于画布、连线和属性面板的交互方向；节点内容遵循「序」的任务模型。

首版以**任务节点**为执行单元：一个节点对应一个现有 `TaskItem`。阶段在可收起的侧栏中导航；里程碑显示为阶段内的检查点和进度标记，不产生隐式依赖。只有用户明确连线，才建立执行顺序。节点图片完全可选，不影响节点是否可执行。

## 2. 信息架构与界面

蓝图卡片仍是入口。打开后进入可调整大小的工作流窗口，顶部保留蓝图名称、目标、完成率和状态，下面是「工作流 / 今日行动 / 时间安排」三个视图。工作流是默认视图；时间轴、周月计划继续作为时间安排的子视图。

```text
┌ 蓝图名称 / 目标 ─────────────── 进度  运行状态   搜索   撤销/重做   更多 ┐
│ 工作流  今日行动  时间安排                 ＋ 添加节点   自动排版   缩放 │
├ 可收起的阶段栏 ┬───────────────────────────────┬ 选中节点的详情 ┤
│ 阶段与里程碑   │       画布：节点、分支、汇合       │ 标题 / 说明     │
│ 阶段完成数     │       点选、拖动、连线、缩放       │ 图片 / 任务设置 │
│ 点击定位节点   │       空白处提示添加第一步         │ 依赖 / 后续影响 │
└───────────────┴───────────────────────────────┴─────────────────┘
```

- 左侧阶段栏默认收起，以节点旁的 `＋` 为主要创建入口；批量创建和加入已有任务可从顶部按钮打开。
- 中央画布支持平移、滚轮缩放、适应窗口、自动排版。连线统一从左向右，分支和汇合可一眼辨认；复杂蓝图可按阶段折叠。
- 右侧详情仅在选中节点时出现；不强迫用户创建节点前填写完整表单。未选中时显示当前可开始的节点和简短操作提示。
- 提供与画布同步的列表视图，供键盘操作、VoiceOver 和密集任务查看；主题色变化与“减少动态效果”设置沿用现有应用偏好。

### 节点卡片

卡片固定宽度，高度随内容变化。顶部是状态图标、标题和操作菜单；中间显示一行说明或首张图片的裁切缩略图；底部显示预计时长、计划日期、阶段以及依赖提示。有图片时显示缩略图和剩余图片数量；无图片时卡片保持紧凑，不出现空白图片区。点图片可放大查看，点卡片空白处选中节点。

状态以文字和图标共同表达，不只依靠颜色：

| 状态 | 卡片提示 | 主操作 |
| --- | --- | --- |
| 等待前置任务 | `等待 A、B 完成`，连线为灰色 | 查看前置任务；可编辑，不能开始或完成 |
| 可开始 | `现在可开始`，边框强调 | 开始 / 直接完成 |
| 进行中 | 显示已开始时间 | 完成 / 标记阻塞 |
| 手动阻塞 | 显示原因，区别于依赖等待 | 解除阻塞 / 编辑原因 |
| 已完成 | 勾选及完成时间 | 查看 / 撤销完成 |
| 已取消 | 显示后续受影响节点 | 恢复 / 调整连线 |

## 3. 低摩擦创建与编辑

1. **空蓝图**：中央显示“添加第一步”。输入标题按回车即创建，日期、象限、时长采用现有默认值；图片和详细设置都可以稍后再加。
2. **串行添加**：悬停或选中节点后，右侧显示 `＋`。点击后输入标题，自动创建下一节点并连线；回车可连续追加。
3. **并行添加**：`＋` 的菜单提供“并行一步”，新节点继承当前节点的前置关系，和当前节点可以同时执行。界面在创建前预览将形成的连线。
4. **插入与汇合**：点击连线上的 `＋` 可在两节点间插入任务；从一个节点的输出拖到另一节点的输入可连线。连接多个前置节点时，界面提示“全部完成后解锁”。
5. **批量创建**：粘贴多行文字，每行一个任务；可选整批串行或整批并行，提交前直接在输入框中修改。也可搜索未归入蓝图的已有任务并加入画布，避免重复创建。
6. **键盘与纠错**：沿用系统的 `Tab` 焦点导航；`⌘Z/⌘⇧Z` 撤销/重做画布操作。连线错误、跨蓝图连线或循环依赖都在提交前提示原因，并保持当前画布状态。

节点位置只影响排版；**连线才影响执行顺序**。移动卡片不会改变依赖。自动排版也不会改动连线。

## 4. 图片交互与保存

- 每个节点允许零张或多张图片；第一张是卡片封面。支持拖入、粘贴、文件选择，通过前移/后移按钮调整顺序，也可移除图片。图片不是创建节点的必填项。
- 画布显示压缩图片的缩略视图；点击后放大查看。导入失败时保留原节点内容并显示错误。
- 导入时将图片缩至适合画布查看的尺寸，并把压缩后的图片数据随节点存入本地数据库。节点不依赖用户原始文件路径，因此移动原图不会使蓝图失图。
- 图片随现有 JSON 快照、文件夹同步和蓝图导出一起传输；旧版无图 JSON 蓝图仍可导入。图片无法解码时显示“图片不可用”，任务和依赖照常可用。
- AI 蓝图与重新规划只接收文字任务信息；图片是否发送给 AI 应由单独的显式操作决定。

## 5. 执行与状态流转

工作流是有向无环图。一个任务的全部直接前置任务为“已完成”时，它才可开始或完成。没有前置任务的节点立即可开始。兄弟分支互不等待；汇合节点必须等所有进入它的分支完成。计划日期只决定何时显示在日历中，不自动解除依赖等待。

执行校验放在 `TaskStore` 的统一操作层，覆盖画布、今日页、四象限、菜单栏、快捷勾选和补记完成等入口。页面可以提示禁用原因，但不能成为唯一的校验层。蓝图暂停时保留当前状态，并阻止节点开始或完成；恢复后按依赖重新计算可执行节点。

关键例外按以下规则处理：

- **前置任务取消**：后续节点保持等待，明确标出“前置任务已取消”，提供替换前置任务或删除连线的操作，不静默放行。
- **删除带后继的节点**：先展示受影响节点，让用户选择重新连线或保留为无前置节点，再确认删除。
- **撤销前置任务完成**：若后继已开始或完成，先展示受影响范围；要求先回退后继，或通过明确的批量回退操作处理，不自动清除执行记录。
- **已完成节点新增前置连线**：如果新前置任务未完成，要求先回退该节点后才能保存连线。
- **旧数据异常**：保留现有任务状态和有效依赖；缺失或跨蓝图引用会阻止执行，可在节点详情中移除失效连线。新增连线会拒绝成环。

今日行动默认优先展示“现在可开始”的蓝图任务；已安排到今天但仍在等待的任务留在“等待前置任务”区，并说明原因。蓝图完成率继续依据任务完成数计算，同时显示“当前可执行 N 项”和“等待 N 项”。

## 6. 数据与落地顺序

现有 `TaskItem.dependencyIDs` 是任务间依赖的唯一事实来源。任务记录新增可选画布坐标与压缩图片数据；任务状态继续复用现有模型。新增字段保持可选，使旧版无图文件仍可导入。阶段、里程碑和无图任务均可原样迁入。

实施分四步：

1. 图校验与统一执行入口，先堵住“等待中仍可完成”的漏洞。
2. 画布、快速添加、连线、自动排版和列表替代视图。
3. 图片导入、缩略图、备份/同步及导入导出。
4. 今日与其他页面联动、AI 草稿适配、迁移测试和真实蓝图交互验收。

首轮验收至少覆盖：串行、并行、汇合；取消和回退前置任务；从任一页面尝试越级完成；有图/无图混排；图片原文件移动或删除；旧蓝图导入、复制、备份恢复；键盘与 VoiceOver 完成添加和执行。


## 7. 实施前的能力与差距

| 能力 | Flutter 当前表现 | 本轮要补齐 |
| --- | --- | --- |
| 手动建立依赖 | 在事项编辑器中可选同蓝图的多个前置任务。普通依赖边可表达串行、分支和汇合，业务规则会拒绝自依赖、重复引用、跨蓝图和循环依赖。 | 在工作流中直接创建和调整整段关系，并预览编辑影响。 |
| 并行执行 | 没有全局单任务运行限制。多个前置条件已满足的事项可逐个开始。事项的批量菜单目前只有完成、取消、安排今天和删除。 | 展示同一时刻可启动的任务，支持多选后一键开始。 |
| 查看流程 | Flutter 画布可缩放、拖动节点，并绘制前置连线。自动列同时考虑前置关系和父子层级，列位置不能用来判断能否并行。 | 展示真实等待条件、并行分支、汇合点，并提供可操作的列表。 |
| 分析与拆分 | AI 蓝图当前将上一非空阶段的全部任务设为下一非空阶段所有任务的前置。同阶段任务之间没有独立依赖建议。 | 提供无需 AI 的拆分和依赖预览，AI 草稿按具体任务建议连线，用户确认后再写入。 |
| 编辑与图片 | 蓝图基础信息和工作流目前由不同弹窗承载。纪念日已有图片选择和本地预览，蓝图与任务节点没有参考图入口。 | 把基本信息、步骤关系和参考图放到同一个编辑工作区，添加后可立即预览。 |

菜单栏标题和桌面小组件目前以第一项进行中任务为摘要。任务列表可以显示多项，摘要在本轮应能辨认当前有多项并行。

## 8. 需求分析

### 用户可以完成的操作

以一次上线为例：

```text
             ┌→ 开发接口 ─┐
确认需求 ────┤             ├→ 联调验收 → 发布
             └→ 准备数据 ─┘
```

1. 添加「确认需求」后，把「开发接口」和「准备数据」设为同一前置任务解锁的两个分支。「联调验收」选择两者作为前置，「发布」只依赖「联调验收」。
2. 完成「确认需求」后，工作流显示两项均可开始。用户选择两项并点击「开始选中」，两项在同一次保存中进入进行中，分别记录开始时间。
3. 任一分支先完成时，「联调验收」仍等待另一个分支，并明确显示待完成的任务。两个分支都完成后，「联调验收」进入可开始列表，由用户主动启动。
4. 用户可以从一段任务清单开始，调整每项交付物和前置关系，在保存前理解哪些工作需要等待、哪些可以同时推进。现有事项可直接加入蓝图并复用原 ID。

### 三种判断

| 用户看到的判断 | 业务口径 |
| --- | --- |
| 流程上可并行 | 在当前有效依赖图中，两项之间双向均无直接或间接等待关系。这一结果以当前连线为依据，界面提示用户核对共用人员、设备和产出。 |
| 现在可一起开始 | 同一蓝图中至少两项同时满足开始条件。它们可能来自不同分支或不同阶段。起始层级和画布位置均不参与判断。 |
| 已安排在同一时间 | 依据日历的执行时间块。并行仅代表可一起推进，资源或时段冲突仍由日历提示，批量开始也不生成或移动时间块。 |

### 执行与关联规则

- **串行**采用完成后开始。一项可以有多个前置任务，汇合默认等全部前置完成。阶段、里程碑本身用于组织与进度汇总。用户可显式把指定的阶段出口任务连到下一阶段的入口任务，实现整体按阶段推进，并保留阶段内部的并行分支。
- **开始条件**为蓝图处于执行中、事项处于可启动状态、依赖有效且全部已完成。允许待办、已延期和未安排的事项主动开始。计划日期仍保留，未安排或安排在其他日期的进行中事项纳入「今日」的进行中区，按事项 ID 去重。
- **暂停和取消**保留已有执行记录。暂停的蓝图不接受新的开始或完成操作，恢复后重新评估。前置取消或手动阻塞时，后继显示具体原因。用户可恢复前置、替换连线或显式移除前置。
- **父子与里程碑**继续汇总进度。父任务用于展示一组工作，新增批量开始只选择可直接执行的节点。已有前置连到父任务时，父任务仍可作为后继等待的汇合点。父任务自身的前置约束父任务的完成，不自动传播给子任务。若希望整个分组都在某项后面开始，应把该项连接到每个入口子任务。已有父任务的执行历史保留。
- **关系变更**影响进行中或已完成节点时，拒绝引入未完成的前置。回退完成前先检查直接和间接的后继，存在已开始或已完成的后继时提示先处理这些节点。删除、替换、插入、批量编辑均在保存前列出受影响节点，保存失败保留当前图。
- **本轮范围**包括蓝图编辑工作区、蓝图和任务参考图、同蓝图依赖、分支和汇合、并行分析、批量启动、手动拆分与可编辑的 AI 草稿。跨蓝图依赖、自动代替用户启动、自动分配人员与资源由独立需求处理。

## 9. 交互方案

### 蓝图编辑工作区

从蓝图卡片打开独立蓝图后，直接进入同一个可调大小的工作区。保留清晰的「编辑蓝图」入口，编辑名称、目标、阶段和里程碑时可以同时查看任务关系与参考图。任务蓝图继续操作原有主任务及子任务，任务参考图随该事项显示。

```text
蓝图名称 · 进度                  添加事项  撤销／重做
阶段和里程碑       工作流 / 执行列表        右侧详情
分阶段定位          画布或任务列表          未选中事项时显示蓝图概览、参考图
                                          选中事项时显示任务、依赖、参考图
```

- **编辑蓝图**时在右侧管理共用的需求截图、流程示意、验收参考等图片。**选中任务**时管理这一步独有的操作截图或结果示例。添加按钮显示当前归属，图片预览也显示蓝图或任务名称。
- 宽窗口并排展示画布和详情。窄窗口通过页签或可返回的详情面板切换，保留已选节点、滚动位置和画布缩放。执行列表按可开始、进行中、等待、已处理显示任务，并提供键盘可达的编辑和开始入口。
- 基本信息、任务和图片编辑使用同一套保存反馈。预览只读，打开和关闭预览均保留表单输入。编辑中切换任务或关闭窗口时，对未保存的修改提供继续编辑或放弃的选择。
- 菜单栏与小组件在有多项运行时显示进行中数量，并可进入今日或展开列表查看每项。节点、依赖和状态均提供文字与辅助功能语义。

### 添加与预览参考图

| 用户操作 | 首版交互 |
| --- | --- |
| 添加一张或多张 | 在「蓝图参考图」或「任务参考图」点击「添加图片」即可多选文件。详情面板的图片区域也接受文件拖入或剪贴板图片，归属取决于投放位置。 |
| 看到添加结果 | 读取成功即显示缩略图，保存前可打开预览、补一句说明、调整顺序或移除。批量添加时逐张反馈，单张失败仍可继续编辑成功的图片。 |
| 在画布上快速识别 | 有图任务显示首张图的紧凑缩略图及图片数量。标题、依赖与状态保持可读。打开缩略图查看大图，点击节点其余区域选中任务。执行列表提供等效的参考图入口。 |
| 看大图、切换图片 | 预览默认完整适应窗口，让流程图和截图边缘可读。支持缩放、实际大小、左右切换和显示当前序号。Escape 关闭预览并把焦点交还给原缩略图。 |
| 管理图片 | 支持修改说明、重新排序和移除。移除后可在保存前恢复，保存后可用工作区撤销。允许蓝图或任务完全无图。 |

### 编排与执行

| 操作 | 预览及确认规则 |
| --- | --- |
| 添加串行下一步 | 新节点以前一项为前置。若点的是已有连线，则把选中的 `A → B` 替换成 `A → 新任务 → B`，保留其余连线。 |
| 添加并行一步 | 新节点继承参考节点的前置，与参考节点各自执行。可在同一预览里把新节点接入选中的汇合节点。选择只并行添加时，预览明确哪些后继仍不等待新分支。 |
| 把多个分支汇合 | 多选分支末端，再指定新建或已有的后继。预览列出实际增加的前置关系，以及汇合任务需要等哪几项完成。 |
| 拆分已有事项 | 粘贴多行标题，每行可补写交付物。初始可选择顺序执行、共享前置的并行分支，或留待手动连线。拆分为子任务时保留原任务及原有后继，原任务按子任务完成情况汇总。 |
| 分析现有流程 | 选中一项后，列表分别展示它等待的任务、等待它的任务，以及在当前关系下可与它并行的事项。可展开查看导致等待的路径。显示多项可启动时提供「全选可开始任务」，用户也可只勾选部分。 |
| 一起开始 | 按钮显示选中数量。提交前后均使用当前数据校验，选择混入等待项或途中发生有效性变化时，列出具体原因并保留勾选，由用户重新确认。 |

AI 拆分沿用先预览后确认的方式。草稿展示可编辑的任务、每条前置关系和理由。新增任务使用草稿内临时 ID，选用已有事项时绑定明确的原 ID。用户可改标题、调整依赖、删除建议节点或选择手动输入。AI 不可用时，多行输入、串并行模板和现有图分析仍可使用。只有用户明确选用 AI 时才发送相关文字。

## 10. 技术方案

### 数据与图分析

- 继续使用任务 JSON 的 `blueprintID` 与 `dependencyIDs`。业务方向统一为「前置 → 后继」，保存时仍在后继记录中存前置 ID。串行、并行、汇合和可启动集合从图中计算。阶段、里程碑、父子关系、坐标、计划日期和执行时间块保留各自含义。
- 从同一工作区快照构建任务 ID 索引、前置和后继邻接表。用拓扑排序校验普通依赖并生成布局层级。用双向可达性查询判定与指定节点结构上可并行的任务，可复用同一快照内的查询结果。用任务状态与完整的前置集合计算当前可启动任务。拓扑层用于画布排列，可启动集合依据实时状态重新计算。
- 另外验证父任务完成条件形成的逻辑等待。可在内存校验图中加入 `子任务完成 → 父任务完成`，例如子任务再把自己的父任务设为前置会形成死锁，应拒绝。该关系不写入 `dependencyIDs`。普通连线和父子归属用不同视觉样式表达。
- 当前文件夹同步、蓝图导出和导入继续复用现有格式。旧数据如果存在缺失引用或已有循环，定位错误节点及受影响的后继，禁止相关节点越过等待，保留用户记录并提供修复入口。用强连通分量定位环中的任务，再沿后继查找受影响范围。同一蓝图中其他有效分支可以继续操作。已保存的旧 AI 蓝图保持原有连线，用户可在新版预览后调整。

### 业务入口与原子提交

| 层 | 改动 |
| --- | --- |
| 规则层 | 把图索引、影响范围、有效性和可启动结果抽成无 UI 的 Dart 逻辑，复用 `TaskRules` 已有的约束。状态转换先校验当前状态，解决先覆盖「阻塞／取消」再校验导致绕过原状态的问题。 |
| `WorkspaceViewModel` | 提供预览图编辑、提交图编辑和按 ID 批量开始的入口。单项开始复用同一执行校验，画布、事项、今日、菜单栏走统一入口。界面只消费可启动结果与明确原因。 |
| 工作区写入 | 使用现有串行写入队列。在锁定的最新快照上核对受影响记录、应用边的增删和状态更新、校验最终状态，成功后一次提交并产生一条撤销记录。预览后发生冲突时返回可读原因。 |
| `WorkflowCanvas` 与执行列表 | 接收同一份图与执行状态。画布拖动只保存节点坐标，提交时按 ID 更新坐标字段，避免旧画布快照覆盖刚保存的依赖和状态。 |
| AI 草稿 | 为现有 `AiBlueprintDraft` 增加可选的任务草稿 ID 和前置 ID。草稿若省略关系，显示未确认的空关系供用户补充。由用户明确选择「按阶段顺序串联」时，才生成跨阶段依赖。校验未知 ID、重复、环和删除节点后遗留的边。 |

批量开始以提交前同一快照判断每个选中 ID，任一项不能启动时整批保留原状态。通过后使用同一个提交时间更新各任务的 `statusChangedAt` 和首次启动项的 `startedAt`。恢复后继续执行的事项保留已有开始时间。重复点击、同步冲突和写盘失败都不会重复刷新计时或只启动半组。完成仍按任务逐项处理，后继在满足条件时进入可开始列表。

### 图片数据与保存

- 蓝图和任务记录新增可选的 `images` 列表。每项含归属范围内的稳定 ID、图片格式、像素尺寸、说明和编码后的图像数据，列表顺序决定首张缩略图。延续纪念日封面的本地保存方式并复用文件选择能力。读入蓝图包时保留图片及顺序，附件 ID 在其蓝图或任务记录内解析。
- 导入时按内容识别格式并确认可解码。首版建议接收 PNG 和 JPEG，保留截图文字与透明背景所需的清晰度。文件大小、解码像素数和单蓝图累计大小设为可配置上限，文档、截图和批量导入的压力测试通过后再确定默认值。超出上限时告知是单张还是累计问题。拖入和剪贴板使用同一校验过程。
- 图片在保存时与所属记录一起写入。视图按显示尺寸按需生成缩略图并缓存，打开大图才解码完整尺寸。JSON 只存一份图像数据，运行时缩略图不进入导出或同步。数据量若使工作区全量写入明显变慢，再评估将附件迁出快照与改造蓝图包的范围。
- 编辑提交按归属 ID 核对和更新图片字段。同步或另一个窗口修改同一组图片时，提示冲突并保留未保存的草稿。取消编辑不写入图片。备份、文件夹同步和蓝图包随已有 JSON 数据携带图片，无图记录兼容旧格式。原文件移走后仍能查看。遇到坏图只在对应位置提示并提供移除或替换操作。
- 图片预览不需要网络。AI 拆分和重新规划仅使用用户确认发送的文字，参考图不会自动随任务发送。

## 11. 迭代顺序

1. **编辑工作区与图片**。合并蓝图基本信息、工作流和选中任务的详情入口，先交付文件多选、缩略图、大图预览、排序和移除，确认保存、撤销、重载和蓝图包往返。
2. **规则与手动编排**。建立统一图索引、死锁校验、原因反馈和单项／批量启动入口，再把并行分析、执行列表、串并行创建、插入和汇合接到同一工作区。
3. **补齐输入与辅助拆分**。接入图片拖放和剪贴板、多行任务与现有事项复用，最后开放可编辑的 AI 依赖草稿。离线拆分可独立完成整个流程。

## 12. 验收场景

| 场景 | 通过条件 |
| --- | --- |
| 串行与分支汇合 | 示例图的初始可启动项只有「确认需求」。它完成后两项均可一键开始。完成一个分支时显示另一个分支为等待原因。两项完成后可以启动联调验收，再解锁发布。 |
| 无关分支与时段重叠 | 不在同一层、没有间接依赖且条件满足的两项能一起启动。同一时间块内存在前后依赖的任务仍须等待。 |
| 批量一致性 | 混入等待项、暂停、删除、同步修改、双击或写盘失败时无半批状态。成功的一批使用一个保存动作和一个开始时间，撤销和重做均保留无关记录。 |
| 跨阶段与父子层级 | 调整阶段和里程碑归属不会隐式连边。允许显式串联跨阶段任务。子任务等待自身父任务产生的死锁被拒绝，父任务结束后能正确解锁后继。 |
| 关系编辑 | 插入中间任务、添加并行分支和多分支汇合均显示真实边的变化。取消预览不写入，保存后重启、导出再导入仍得到相同关系。 |
| 异常数据与状态 | 普通环、跨蓝图引用、缺失前置、前置取消和回退完成均给出原因。画布、事项、今日和菜单栏对同一任务的启停判定一致。 |
| 拆分与可访问性 | 无 API Key 可用手动方式走完拆分、确认、开始和汇合。AI 草稿可改边和撤回。小窗口、大字体、键盘和 VoiceOver 可读出状态、等待原因与批量操作结果。 |
| 编辑与图片预览 | 在同一窗口添加蓝图级与任务级参考图，保存前即可预览。放大查看后能返回原任务继续编辑。小窗口能完整查看图片和保存操作。 |
| 图片持久化与异常 | 重载、同步和蓝图包导入后，图片、顺序和说明一致。取消编辑不会留下附件。移除后可撤销，原文件移走不影响预览，坏图与超限提示定位到对应图片。 |


## 13. 拓展能力与使用场景

目标是让蓝图在执行过程中持续回答三个问题：哪项工作当前卡住了进度，调整一条分支会影响哪些交付，以及做到什么算完成。

| 能力 | 位置与交互 | 用户可以据此行动 |
| --- | --- | --- |
| 执行概览 | 在蓝图标题下展示「可开始」「进行中」「等待」「逾期」计数。点击计数筛选执行列表，同时保留节点在画布上的上下文。等待项显示直接原因，可展开实际阻塞链。 | 定位优先处理的任务，区分手动阻塞、等待前置、暂停和日期逾期。 |
| 关键路径与里程碑风险 | 选中目标任务或里程碑后，高亮限制该目标最早完成时间的链路。并列的链路同时标出。缺少估时或存在未解决阻塞时，显示数据缺口和风险来源。 | 判断应先解决哪个分支，也能看到哪些工作有余量，适合穿插推进。 |
| 改期推演与基线对比 | 从任务菜单进入「预演调整」，试填新日期或增加耗时，查看会受影响的后继、预计完成时间、里程碑风险和可能冲突的日历时间块。用户可以只保存根任务的变化，也可以选择合规的后继调整。 | 在改动前判断是提前处理阻塞、调整依赖、移动时间块，还是接受里程碑推迟。 |
| 里程碑验收与成果 | 在里程碑面板填写验收条件，勾选检查项，引用步骤截图作为成果。关联任务处理完后显示「待验收」，验收通过后记录结果。蓝图概览显示还缺哪些事项或检查项才能收尾。 | 例如把联调通过的截图留在验收记录里，供后续定位和复盘。 |
| 复盘与复用 | 收尾时显示完成成果、影响过里程碑的变更及仍需跟进的事项。可生成可编辑的本地复盘草稿，也可把整理后的流程另存为模板，下次从同样的步骤和连线开始。 | 将有效的顺序、并行分支、里程碑检查条件和通用参考图复用于类似项目。 |

沿用上线示例，若「开发接口」剩余 4 小时，「准备数据」剩余 2 小时，两条分支都能立即开始，联调还需 1 小时。只按依赖和工时计算，联调最早在 5 小时后结束，由接口分支决定。数据准备增加 1 小时仍留有余量，增加 3 小时则会把联调最早结束时间推迟 1 小时。若日历另有会议，推演在相应任务旁提示时间冲突，供用户选空档。

## 14. 拓展规则与技术方案

### 进度判断与影响分析

- 继续使用同一份依赖图派生执行概览、阻塞链和影响范围。每项按任务 ID 计数，阶段、汇总父任务和里程碑以摘要展示。逾期是可与进行中或等待同时出现的日期提示，只有明确的截止时间才参与逾期判断。
- 从目标向前取依赖闭包，再沿拓扑顺序计算剩余工作链。每一汇合点的最早开始取各前置最早完成时间的最大值，已完成任务无需再计剩余工时。进行中任务采用用户确认的剩余工时。父任务汇总子任务时间时不重复计入父任务估时。
- 显示三个独立值：**总剩余工作量**是各待执行事项的估时之和，**流程最短剩余时间**是当前依赖约束下的最长工作链，**当前计划预计完成日期**由已排时间、工作时段和用户选择的空档决定。只有对应数据足够时显示准确到日期的预计值。缺估时、循环或无可通过的前置时，计算已知部分并说明哪些结果待确认。
- 优先复用现有 `estimatedMinutes`、计划日期、执行时间块、`CalendarWorkHours` 和里程碑关联。估算与筛选是从当前快照获得的结果，随数据刷新。一个里程碑的风险分析只沿其关联任务的前置展开，其他分支仍可执行。

### 计划基线与改期推演

- 初次认可计划时提供「设为计划基线」，记录当时纳入计划的任务、计划日期、截止、估时和必要的依赖。之后区分首次基线、当前计划和实际完成。重设基线需要显式操作，原基线保留在该蓝图的规划历史。
- 推演在内存快照上执行，复用图校验、工作时段、时间块冲突与现有重新规划历史。结果区分**图上受影响**和**实际需要改期**，显示每一项的原因。锁定安排、已完成任务以及用户未选中的记录保留，发生冲突时允许只调整根任务并保留风险提示。
- 确认提交时重新核对受影响任务及关键依赖。合规改动以一次工作区写入保存，记录改动前后、理由及当时受影响的里程碑。一批改期可撤销，预览中的变化在关闭后不写入。

### 验收、复盘与模板

- 里程碑新增可选验收检查项。没有检查项时保留现有完成规则；有检查项时，任务全部满足后进入「待验收」，任务与必需检查项均满足后由用户确认通过。关联任务重新打开后重新评估当前状态，既有验收记录仍可查阅。
- 验收可引用现有参考图，使用所属任务 ID 和图片 ID 定位。同一张图片可被验收引用而无需复制。源图被移除时，旧记录标明附件已移除，保留验收结论。复盘草稿可引用通过的检查项、实际进度、延期理由和后续事项，并复用现有本地日报与周复盘的可编辑流程。
- 将蓝图保存为模板时，默认复制步骤、父子结构、依赖、里程碑验收条件和相对日期。默认排除实际状态、执行计时、历史记录和任务成果图，用户可以选入需要复用的通用参考图。从模板新建时重映射蓝图、阶段、里程碑和任务 ID，并按选定起始日期重新计算相对排期。
- 沿用现有 [里程碑与规划记录](../flutter/lib/src/workspace.dart)、[重新规划](../flutter/lib/src/replan.dart)、[工作时段与空档](../flutter/lib/src/calendar_plan_logic.dart) 及 [蓝图包 ID 重映射](../flutter/lib/src/blueprint_transfer.dart)。模板保存和复制继续走工作区的原子提交路径。

## 15. 后续交付顺序

1. **优先交付执行判断**。在首批编辑、图片和串并行编排可用后，加入执行概览、阻塞链和目标关键路径。先确定下一步该做什么。
2. **加入变更推演**。交付基线、改期影响和选择性提交。计划延期时，用户能看清代价再调整。
3. **补齐收尾和复用**。交付验收条件、图片成果、本地复盘，并把有效的流程另存为可复用模板。

## 16. 拓展验收场景

| 场景 | 通过条件 |
| --- | --- |
| 分支耗时不等 | 两条分支耗时不同，正确识别限制目标完成的链。短分支在余量内延长时，目标预计值保持原有结果。并列最长时两条链都可辨认。 |
| 缺失估时或前置阻塞 | 展示缺项及阻塞链，用户仍可操作正常分支。预计完成日期只在已有足够信息时显示。 |
| 改期撞上锁定时间块 | 推演能指出受影响后继和冲突时间段，保留锁定项。取消预览后原数据完整，提交后可从历史查看原因并撤销。 |
| 里程碑剩余检查 | 关联任务全完成但仍有必需检查未通过时显示「待验收」。检查通过并确认后可回看结论和所引用的成果图。 |
| 另存为模板再创建 | 新蓝图保留分支、汇合、相对排期和验收条件，并使用独立 ID。执行历史与私人截图保持在原项目内。 |
