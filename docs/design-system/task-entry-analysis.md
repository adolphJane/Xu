# 更快、更聚焦地添加任务：审计与设计方案

本方案基于当前 macOS 与 iOS/iPadOS 目标的实际入口、表单和 `TaskItem` 字段。它是交互设计提案；[可交互 UI 设计稿](mockups/task-entry-concept.html)使用示例文字，不连接用户数据，也不改变现有业务逻辑。

## 1. 现在的任务如何进入系统

| 场景 | 当前路径 | 有利之处 | 主要阻力 |
| --- | --- | --- | --- |
| macOS 全局 | 顶部“添加事项”或 `⌘N` → `TaskComposerView` | 打开后标题自动聚焦；标题是唯一必填；支持连续添加、已完成记录、AI 草稿 | 默认窗口约 630×555pt；在输入前同时看到三种模式、蓝图、类别、日期及“更多设置”，使“只记一句话”看起来像多步骤填写。全局默认“今天”隐藏在日期选择的初始状态里。 |
| macOS 分类 | 页面“新建任务” → 同一表单，预填类别 | 分类上下文已带入 | 类别预填与全局表单并列的其他控件一起出现，用户仍需确认自己是否还要设置蓝图和日期。 |
| macOS 蓝图 | 蓝图页面新建 → 同一表单，预填蓝图；工作流另有内联快添 | 已存在“上下文预填”和“快速输入”的基础 | 入口不同，获得的体验不同；内联快添未形成全局一致的捕获模式。 |
| iOS 今日 | 顶部“添加事项” → `IOSTaskComposerView` 的系统 `Form` | 系统表单清楚，标题必填，保存入口明确 | 一开始仍展示备注与四象限；没有“今天 / 明天 / 收集箱”可见选择。标题输入没有自动聚焦。 |
| iOS 分类 | 底部加号 → 同一表单，预填类别 | 单手容易触达，保存时继承类别 | 分类预设在表单中不可见；用户无法在添加时核对或改选；日期安排与桌面不一致。 |

当前 `TaskItem` 已具备标题、类别、蓝图、计划日期、截止日期、备注、象限、预计时长等字段；macOS 现有 `save()` 也已支持“今天 / 明天 / 选日期 / 收集箱”。因此第一轮可以只改**信息层级与入口**，不需要模型、SwiftData 或备份迁移。iOS 若补齐安排能力，应复用共享模型的现有 `scheduledFor` 与 `status` 语义，并验证现有状态规则。

## 2. 人体工程学与心理学判断

| 判断 | 设计动作 | 证据边界 |
| --- | --- | --- |
| 添加任务通常从一个短暂念头开始，先让人把核心动作写下。 | 打开即聚焦标题；标题单独成区；非必填设置折叠。 | Apple 建议文字输入以短而明确的信息为主，并按逻辑顺序移动焦点；隐藏暂不相关的细节有助于突出最常用的控制项。[Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields)、[Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)。 |
| 入口时同时要求选择模式、蓝图、类别、日期，会增加开始输入前的决策。 | 主路径仅“输入标题 → 保存”；可选项只显示当前归属与安排的摘要，需要时再展开。 | Hick 的经典实验观察的是**选择反应任务**，不能直接推算此 App 会快多少；这里仅把“减少初始选择”作为待验证的设计假设。[Hick, 1952](https://www2.psychology.uiowa.edu/faculty/mordkoff/InfoProc/pdfs/Hick%201952.pdf)。 |
| 自动代填可以省操作，但保存位置不透明会造成错误与不信任。 | 从分类/蓝图/今日进入时预填对应上下文，并在主界面以文字显示；全局入口明确写出默认目的地。 | Apple 强调清晰的层级、简洁措辞和用户控制；这是针对当前项目的推论。[Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles)、[Writing](https://developer.apple.com/design/human-interface-guidelines/writing)。 |
| “何时做”有助于执行，却不应成为捕获瞬间的门槛。 | 提供“收集箱 / 今天 / 明天”单次选择；自定义日期与截止日期放入展开区。 | 实施意向研究支持把行动与具体情境连接，但并不意味着每一条新任务都必须立即排期。[Gollwitzer, 1999](https://www.socmot.uni-konstanz.de/publications/implementation-intentions-strong-effects-simple-plans)。 |
| 手机添加多由拇指和屏幕键盘完成。 | 新建入口靠近底部；保存按钮位于键盘上方的安全区域；核心触控区域 ≥44×44pt；不依赖小图标。 | Apple 的触控目标建议是至少 44×44pt；原生 sheet 适合完成与当前页面相关的单一任务。[UI Design Dos and Don’ts](https://developer.apple.com/design/tips/)、[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)。 |

这些依据不证明本方案一定提高效率。最终以真实使用测试中的录入时间、误分配和取消率验证。

## 3. 核心交互：先捕获，再安排

### 默认状态

1. 打开轻量添加界面，焦点直接在“要做什么？”输入框。**标题是唯一必填**。
2. 输入框下仅显示两个可以修改的摘要：**归属**（类别或蓝图）与**安排**（收集箱 / 今天 / 明天）。摘要使用文字，避免只靠图标或颜色。
3. 主操作是“添加任务”。空标题时禁用；保存成功后给出简短可感知反馈。`Esc`/取消关闭；macOS 保持明确的键盘路径，并提供“连续添加”而不强迫关闭重开。
4. “更多设置”按需展开备注、项目、四象限、预计时长、截止日期及依赖。已完成记录和 AI 生成保留在添加入口旁的次级菜单，不占普通任务的首屏。

### 上下文预设

| 从哪里打开 | 默认归属 | 默认安排 | 首屏必须告知 |
| --- | --- | --- | --- |
| 全局入口/快捷键 | 未分类 | **收集箱**（建议新默认，需单独确认数据语义与迁移后再实现） | “未分类 · 收集箱” |
| 今日页 | 未分类，除非有其他明确上下文 | 今天 | “今天” |
| 某个分类 | 当前分类 | 收集箱；若入口位于该分类的“今日任务”场景，则今天 | 分类名与安排 |
| 蓝图/阶段 | 当前蓝图/阶段 | 沿用当前蓝图上下文中的既有安排规则 | 蓝图/阶段名与安排 |

不要通过用户输入中的“明天”等文字**静默**改变时间，也不要自动把任务交给 AI。未来若做自然语言识别，应先显示可撤销的解析建议，由用户确认。被预填的字段应能在同一界面改选。

### 平台表现

- **macOS：**保留现有 `⌘N` 和顶部主按钮；使用紧凑 sheet/浮层，首屏高度随展开状态变化。`Tab` 顺序为标题 → 归属 → 安排 → 更多设置 → 保存。保留 `TaskComposerView` 的现有保存规则和连续添加能力，先改可见层级。
- **iPhone：**保持系统 sheet；标题进入后聚焦，底部主按钮固定在键盘上方安全区域。取消位于 sheet 顶部。当前分类或日期显示为可点击摘要；使用系统 `Menu` / `Picker` / `DatePicker` 实现选择。
- **iPad：**同一内容使用居中、受限宽度的 sheet，并支持外接键盘的焦点与提交；不把 iPhone 底部按钮无限拉宽。
- **无障碍：**标题、归属、安排、保存顺序清楚；VoiceOver 朗读实际值，例如“分类，工作”“安排，收集箱”；动态字号下摘要可以换行；Reduce Motion 时不做弹跳式展开。

## 4. 设计稿与落地边界

[交互式设计稿](mockups/task-entry-concept.html)可切换 macOS / iPhone、浅色 / 深色和入口上下文，也可展开“更多设置”。设计稿中的任务、分类和保存反馈均为**演示数据**；它展示信息层级及位置关系，不模拟 SwiftData 存储。

设计稿遵循现有暖纸张品牌语言：页面底色、卡片面、强调色与边界分层；主操作只出现一次，表单控件的实际实现应优先采用 SwiftUI 原生控件和设计系统 token。HTML 像素值仅用于沟通比例，落地时以 `AppSpacing`、`AppTypography`、`AppRadius`、平台安全区域和 Dynamic Type 为准。

## 5. 建议的验证方式

先针对**普通待办**做小范围原型测试，比较现有表单和新方案：从点击入口到成功保存的时间（中位数和较慢用户的 P90）、取消率、空标题尝试、保存后立即改类别/日期的比例，以及能否在不解释的情况下找到收集箱。至少覆盖全局、今日、分类三个入口，以及键盘、VoiceOver、大字号与深色外观。若误分配增加，优先调整默认位置与文案，再考虑更智能的自动化。

建议实施顺序：**先统一入口与上下文摘要 → 再收紧 macOS 普通待办首屏 → 补齐 iOS 归属和安排 → 最后优化 AI 与已完成记录的次级入口**。每一步都保留原有字段与保存行为，并按 `AGENTS.md` 分别构建和核对两平台。
