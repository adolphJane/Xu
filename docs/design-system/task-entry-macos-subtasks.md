# macOS 聚焦添加与快速子任务

本轮只设计 macOS 14+。这是[上一轮任务添加分析](task-entry-analysis.md)的收窄方案；[可交互 macOS 设计稿](mockups/task-entry-macos-subtasks.html)用演示任务表现“无子任务”和“连续录入子任务”两种状态，不连接用户数据，应用已按此交互落地；HTML 仍只展示演示数据。

本方案的产品前提已明确为：[任务是基础，蓝图 / 列表 / 四象限是同一批任务的不同视图](task-views-architecture.md)。添加子任务后默认进入该主任务的蓝图视图，不另建一份“蓝图任务”。

## 现有能力与缺口

- 顶部“添加事项”和 `⌘N` 已进入 `TaskComposerView`，标题自动聚焦、唯一必填；当前普通待办的首屏仍显示模式选择、关联蓝图、类别与排期。
- `TaskItem.parentTaskID` 和 SwiftData 持久化已存在。AI 草稿保存时会创建父任务与关联子任务；普通待办模式尚未提供手动子任务输入。
- `TaskCard` 只用箭头标识子任务，列表仍逐项展示；子任务本身是独立 `TaskItem`，会进入任务数和相应筛选。删除父任务时，当前 `TaskStore.delete` 会把子任务改为独立任务。设计不能把它暗示成只存在于父任务内部的轻量清单。

## 核心方案

普通待办首屏按顺序显示：**主任务标题 → 可见的归属/安排摘要 → “＋ 添加子任务” → 更多设置 → 保存**。打开后焦点落在标题；不想拆解的用户输入标题后直接保存。子任务入口处于标题之下，便于想要拆解时顺手使用，但初始不占用多行表单。

### 快速子任务交互

1. 点击“＋ 添加子任务”，出现一行单行输入，立即获得焦点。
2. 输入并按 `Return`，当前文字加入子任务列表，下一条空输入保持焦点；用户可以连续录入，无需反复点加号。
3. 每条子任务可在保存前直接编辑或移除；允许相同标题，内部草稿项必须用稳定 ID 标识，不能以标题做 `ForEach` 身份或“一次删掉同名项”。
4. 空输入按 `Return` 不新增；按 `Escape` 只退出当前空输入，不丢弃已写的主任务与子任务。关闭整个 sheet 前，如有未保存文字，应有明确的放弃提示。
5. 点击主保存或 `⌘Return` 时，若当前子任务输入非空，连同已列出的项目一起保存；空白项忽略。主标题仍是唯一必填。
6. 保存按钮旁的摘要明确写出“将创建 1 项主任务 + N 项子任务”，有子任务时主按钮写“添加并查看蓝图”；没有子任务时只写“将创建 1 项任务 / 添加任务”。保存成功后反馈实际创建数。未启用连续添加时自动打开蓝图视图；连续添加时保留输入焦点并提供“查看蓝图”入口。

### 数据与状态语义

提案沿用现有 `TaskItem` + `parentTaskID`，不新增数据库字段。子任务继承主任务的类别、象限和安排；若从已有蓝图进入，也继承其蓝图/阶段关联。普通入口生成的任务树不需要虚构 `blueprintID` 或目标日期，蓝图视图从父子关系派生。快速录入阶段不要求逐条排期；独立的截止日期、预计时长等仍可在保存后进入任务详情调整。主任务与子任务的完成状态彼此独立，不因为子任务完成就自动完成主任务。

保存需要被视作一次用户操作：先验证所有输入及状态规则，再创建主任务与子任务并给出单次成功反馈。现有 `store.add` 是逐项插入/持久化；实施时要检查部分失败、列表顺序与连续添加后的清空范围，避免出现只保存一部分却提示全部成功。此处属于实现风险，不在设计稿中修改存储机制。

**三个视图的呈现是配套问题。**现有列表会把子任务作为独立行显示；当前蓝图画布只使用 `dependencyIDs` 连线、只读取 `blueprintID` 下的任务。要让子任务自动形成蓝图，需增加按 `parentTaskID` 派生的层级布局，不能用依赖关系冒充父子关系。列表可让父任务行显示“2/3 已完成”并展开子任务；四象限继续使用每个任务自身的象限。具体兼容策略见[视图架构](task-views-architecture.md)。

## 人机交互理由

- 标题先行、进阶字段后置，遵循 Apple 对[渐进展示](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls)和[文字输入](https://developer.apple.com/design/human-interface-guidelines/text-fields)的建议。
- `Return` 后保留子任务输入焦点，减少手从键盘移到指针再返回的往返；`Tab` 能按标题、归属、安排、子任务、更多设置、保存的逻辑顺序访问。macOS 用系统焦点环显示位置，参照 Apple 的[焦点与选择](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection/)。
- 子任务是可选的拆解帮助，不设置最低数量，也不强迫用户在捕获念头时规划完整步骤。给出了清楚的目标与具体下一步后，可能有助于执行；这只是依据[实施意向研究](https://www.socmot.uni-konstanz.de/publications/implementation-intentions-strong-effects-simple-plans)提出的产品假设，仍需验证。

## 设计稿及实施边界

设计稿保留现有暖纸张视觉语言，展示浅色/深色与不同入口预设；只考虑 macOS 窗口、键盘、指针与 VoiceOver。HTML 中的任务和保存提示仅为演示。真正落地时使用 `AppSpacing`、`AppTypography`、`AppRadius` 和已有主题偏好；子任务输入优先使用原生 `TextField`，更多设置使用 `DisclosureGroup`，不把 HTML 控件直接移植到 SwiftUI。

验证应覆盖：只填标题、连续添加 3 条子任务、重复标题、空白行、超长中文、从分类/蓝图预填、切换安排、取消未保存内容、连续添加、键盘全程操作、VoiceOver 与字体放大。统计录入耗时及保存后立即编辑/删除子任务的比例，再决定是否调整默认布局。
