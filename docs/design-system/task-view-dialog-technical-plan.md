# macOS 任务视图弹窗改造技术方案

状态：第一至第三阶段已实施（2026-10-19）；后续增强仍按 P2 独立评估。范围为 `TaskBlueprintView` 及从中进入的 `TaskEditor`。以[任务视图架构](task-views-architecture.md)和本次界面审计为依据。第一轮只调整 macOS 呈现和交互，沿用现有 `TaskItem`、`parentTaskID`、`dependencyIDs`、SwiftData、JSON 备份和文件夹同步格式。旧 `BlueprintDetailView` 的阶段及工作流能力保持独立。

## 目标交互

弹窗顶部只保留根任务名称、明确标为「全部后代」的完成进度、蓝图/列表/四象限切换，以及紧凑工具区。点击任一视图的任务先选中；所选任务保持在视图切换后不变。选中区显示完整归属路径、状态、计划/截止和「编辑」「添加子任务」，状态动作继续遵循 `TaskStore` 的阻塞规则。菜单的显式「编辑」继续直接打开编辑弹窗。

蓝图展示父子关系；列表强调层级与执行信息；四象限按每项任务自己的象限分组。三种视图始终读取同一组任务 ID。无论从哪个视图添加子任务，都以所选任务为父任务；添加成功后保持输入焦点，并可定位新任务。

## 第一阶段：修正退出与草稿语义（P0）

涉及 `Sources/Quadrant/TaskEditor.swift`，不修改全局 `AppDialog` 的生命周期。

1. 把关闭、取消、Escape、遮罩点击和「查看蓝图」统一交给 `requestExit(destination:)`。目的地为关闭或查看蓝图，先检查草稿，再决定保存、放弃或继续编辑。
2. `hasUnsavedChanges` 纳入未提交的 `newChildTitle`，并按可见字段比较；「查看蓝图」不得直接调用 `closeEditor()`。保存函数返回成功/失败，只有成功才安排关闭后的导航。保存失败仍停留在编辑页并显示当前 `formError`。
3. 对无改动情况直接关闭；有改动时给出「保存并继续」「放弃修改并继续」「继续编辑」。目的地先记录在呈现层，导航由对应的 `appDialog(..., onDismiss:)` 在退场完成后执行；不要把 `onDisappear` 当成退场完成事件。
4. `TaskEditor` 从任务视图内打开时传入 `blueprintAlreadyPresented`（或等价环境值）。此时「查看蓝图」表示返回下层现有弹窗，避免向主窗口再发送一次 `showTaskBlueprint` 造成重复弹窗；从其他入口打开时在宿主的 `onDismiss` 回调里使用现有导航通知。需检查 `Views.swift`、`BlueprintViews.swift`、`BlueprintWorkflowView.swift` 和嵌套子任务编辑入口。
5. 已提交的子任务目前通过 `TaskStore.addChild` 立即保存。第一轮保留这个业务语义，在子任务区固定显示「已添加的子任务会立即保存；取消只放弃尚未保存的字段」；提交失败就近显示原因并保留输入。若 `newChildTitle` 还有文字，「保存修改」与「保存并继续」先提示按回车添加或清空，不得直接关闭并遗失这行文字。避免让底部「保存修改」暗示可以撤销已添加子任务。真正的跨字段、跨子任务一并提交需要新的事务 API，单独评估。
6. 保存已有任务时先按 ID 读取 `TaskStore` 中的最新值，只覆盖表单可编辑字段；保留可能已由子任务操作更新的完成状态、完成时间和执行状态，避免用弹窗打开时的旧快照覆盖实时变化。

验收：改动任务名称后点击「查看蓝图」，不会直接丢失草稿；三种确认结果分别正确；空标题、保存失败及未提交子任务文字均不触发错误导航；在任务视图里进入编辑再返回，只保留原有蓝图弹窗。

## 第二阶段：统一选择与操作（P1）

涉及 `TaskBlueprintView.swift` 和 `Views.swift` 中的 `TaskList`、`TaskListTreeRow`、`TaskCard`。新增参数提供默认值，不改变其他页面的现有点击行为。

- `TaskBlueprintView` 以 `selectedTaskID: UUID?` 作为唯一选择状态。`selectedTask` 仅从当前任务树的 `allTasks` 解析；任务删除或移出该树时回退到根任务，根任务不存在则展示原有不存在空态。
- 蓝图节点保持单击选择。向 `TaskList` 透传独立的 `onSelect` 与可选 `onEditTask`；任务视图传入「单击选择」和「显式编辑」两个动作。四象限的 `TaskCard` 同样传入这两个闭包。`TaskCard` 的默认值保持其他调用处原语义；完成、恢复和更多菜单不依赖行选择事件，避免点击按钮时同时触发选择。
- 给列表/四象限卡片增加可选 `isSelected` 呈现和辅助功能选中语义。边框之外显示「当前选中：任务名」文字，颜色不作为唯一反馈。切换视图、折叠分支后仍保留选择；若选择项暂时不在画面内，提供「定位所选」。
- 将「添加到：…」改为清晰的目标区。归属路径允许换行或横向查看，输入框标签包含父任务名；编辑和添加按钮就近布置。行内菜单仍可选择「添加到此任务」，并把输入焦点移到快速添加区。
- 顶部统计写为「全部后代 X/Y 已完成」，行内写为「直接子任务 X/Y 已完成」。保持现有计算和自动完成规则，只澄清不同范围。重复的默认「未分类」「未归类项目」在任务视图的紧凑行中不显示，真实分类和项目仍显示。

验收：从任何视图选择同一个 ID，另外两种视图和添加目标同步；菜单编辑仍能打开该任务；完成/恢复按钮只执行一次状态操作；根任务与深层子任务的计数口径清楚。

## 第三阶段：布局与浏览（P1）

涉及 `TaskBlueprintView.swift`，建议把纯布局计算抽到同目录 `TaskTreeLayout.swift`，不修改任务模型。

- 蓝图画布由目前的「遍历一个节点就下移一行」改为以子树计算布局：先计算每棵子树的高度，叶节点顺序排列，父节点放在直接子树的纵向中点；X 由层级决定。仅对可见节点画父子曲线，并保持连线语义为「拆解关系」。
- 默认先采用紧凑的节点和间距，并按内容实际边界设置画布尺寸。提供「适应全图」「定位所选」；当树大到无法在可读字号下完整容纳时保留滚动，不强行缩小文字。较大的树可折叠分支，折叠状态只属于界面状态。
- 四象限使用顶端对齐的两行两列 `Grid` / `GridRow(alignment: .top)`；窄弹窗切换为单列。空区用紧凑说明和数量，内容区按可用高度滚动。增加仅在本弹窗生效的「待处理 / 全部」筛选，默认值需与进入入口的意图一致；筛选不修改任务状态。
- 顶部工具区收紧，弹窗轮廓在切换三种视图时保持稳定。继续由 `appDialog` 负责宿主尺寸、遮罩、转场和焦点恢复，业务页不新增独立窗口或 sheet。

验收：审计样例的一个根任务、四个后代在常见窗口尺寸下可看清结构；不再出现四象限左上区下沉。长中文、深层树和窄窗口仍能访问全部节点与操作。

## 后续增强（P2，独立评估）

任务视图内部可增加按名称搜索、状态筛选与展开/收起全部。若要显示前置依赖，用不同线型及方向箭头表示 `dependencyIDs`，加图例说明它与父子拆解关系的区别；不得把父子线写入 `dependencyIDs`。若要让编辑页新增子任务也参与「保存修改」的统一事务，需要在 `TaskStore` 增加一次校验并写入父任务与新子任务的 API，同时补 SwiftData/JSON/同步往返测试；不能只把 `addChild` 延后循环调用，因为中途失败会留下部分已保存子任务。

## 验证与交付

实现时先为纯布局计算增加多层树、宽树、长标题和单节点的必要测试，并用内存 `TaskStore` 验证自动完成后的进度范围和保存时的实时状态保留。草稿退出路径、选择 ID 保持、创建失败保留输入和弹窗退场后的导航由预览隔离数据及真实窗口交互验收。macOS 真实窗口检查浅色/深色、正常/放大字号、窄窗口、长中文、空树与有数据状态、VoiceOver、键盘、Reduce Motion，截图对照审计样例。

每个实施批次更新 `docs/design-system/rollout.md` 的范围、组件映射与结果。代码修改后运行 `swift test` 和 `zsh scripts/build-app.sh`，确认 `dist/序.app` 产物，再执行 `open dist/序.app` 并检查窗口。若修改共用 `TaskStore` 或任务数据行为，再验证 iOS/iPadOS 源码编译兼容；第一至第三阶段若只改 macOS 呈现层，按仓库规则只验 macOS。
