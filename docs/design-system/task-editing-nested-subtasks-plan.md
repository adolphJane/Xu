# 已创建任务的编辑与多级子任务规划

## 目标与范围

用户能从事项列表、四象限、今日、分类和蓝图进入同一项任务的详情，修改标题、备注、类别、象限、日期、时长等字段；保存后所有视图立即反映同一任务 ID 的变更。任意任务（含子任务）都能添加下一级任务，形成多级任务树。AI 图片生成的主任务和子任务保存后遵循同一套操作。

本轮同时覆盖 macOS 14+ 与 iOS/iPadOS 17+ 的现有任务入口。任务与执行依赖维持独立语义：`parentTaskID` 只表达归属，`dependencyIDs` 才决定执行阻塞。使用现有 `TaskItem` 字段，不引入新模型或备份格式。

## 当前代码核对

| 位置 | 已有能力 | 待解决的问题 |
| --- | --- | --- |
| `TaskItem` / `StoredTask` | `parentTaskID` 已持久化，也进入 JSON 备份与同步 | 缺少统一的父子关系校验入口；添加已有任务的子任务目前走返回值为 `Void` 的 `add` |
| `TaskTreeProjection` | `rootID`、`descendants` 已能遍历多级关系并规避循环读取 | 尚无「直接子项 / 路径 / 各层进度」供界面共用的投影；无写入校验 |
| macOS `TaskEditor` | 能编辑多数任务字段并通过 `store.update` 保存 | 需要复现用户遇到的无法编辑情形；表单没有添加、查看下级任务的入口，保存失败反馈不贴近表单 |
| `TaskBlueprintView` | 能显示多级节点，图中节点可打开编辑 | 顶部新增子任务依赖打开时传入的 `focusTaskID`；点击别的节点没有改变添加目标，容易写入错误父项 |
| `TaskListTreeRow` / `TaskCard` | 列表递归展开，卡片可打开编辑 | 递归在第 20 层停止；卡片进度只统计直接子项；「更多」菜单缺少明显的编辑和添加下级操作 |
| iOS `IOSTaskDetailView` | 能看任务和更新执行状态 | 详情目前只读，没有编辑、添加子任务和层级导航 |

## 产品规则

1. **任意层级可继续拆解。**不限制数据层级；界面通过滚动、缩进和面包屑处理较深树。新增下级任务时显示目标父任务标题，默认继承其项目、类别、蓝图/阶段、象限和安排状态；用户随后可以独立修改这些字段。
2. **任务身份稳定。**编辑不新建任务 ID，不改变创建时间、完成历史、图片或工作流位置；成功保存后列表、四象限、今日和蓝图读取同一份数据。
3. **进度定义明确。**任务行显示直接子任务完成数；任务树顶部显示全部后代完成数，并注明统计范围。完成子项不会自动完成父项，父项完成也不会自动更改子项状态。
4. **归属变更受校验。**允许在同一任务树内给任务更换父项；不能选自己或自己的后代，不能形成循环，也不能指向不存在的任务。跨蓝图移动先检查依赖连线，并明确是否连同后代迁移；首批只提供安全的整棵子树迁移。
5. **删除层级节点时保留后代。**删除有子项的任务需说明影响；确认后把直接子项接到被删项的父项（根节点被删时，直接子项变为根任务），各子项自己的后代关系保持不变。已有前置依赖限制仍先检查。
6. **保存失败不关闭界面。**空标题、无效父项、循环、跨蓝图依赖冲突和持久化错误要在当前表单显示原因；原输入保留。关闭未保存编辑时提示放弃。

## 分阶段实施

### 阶段 1：修复编辑闭环

- 在 macOS 真实开发版逐一复现「创建后无法编辑」：从今日、事项列表、四象限、分类及蓝图打开主任务与子任务，记录是入口无响应、表单字段不可改，还是保存未生效。
- 统一各任务卡片和节点的「编辑」显式操作；卡片点击继续打开详情。`TaskEditor` 使用最新的 `store.tasks` 任务值加载，保存时用同一 ID 调用 `store.update`；成功才关闭，失败在表单展示 `actionMessage`。
- iOS 详情增加系统导航栏「编辑」，以 `Form` 编辑已有字段；保存复用同一 `TaskStore.update` 规则。
- 验收：AI 生成、手动创建及历史数据中的任务均可编辑；保存后重新打开、切换视图、重启应用，字段和 ID 一致。

### 阶段 2：统一父子写入规则

- 给 `TaskStore` 增加返回成功/失败结果的 `addChild(to:)` 与 `moveSubtree(...)`，集中验证父任务存在、ID 唯一、无循环、蓝图归属和现有工作流规则。一次操作只写入一次任务集合，避免部分成功。
- `TaskTreeProjection` 增加直接子项、祖先路径和整棵子树辅助方法，所有入口共用；保留对旧数据中孤儿关联的只读容错。
- 删除中间节点时按上述提升规则一次更新父子关系；对有后代的节点显示确认和后果说明。
- 验收：子任务可新增孙任务及更深层级；错误归属不会写入；旧 SwiftData、JSON 备份和文件夹同步数据能原样读取和往返。

### 阶段 3：macOS 层级交互

- 在任务详情加入「子任务」分区，列出直接子项及状态；提供「添加下级任务」。从任意子项打开详情后，分区操作作用于当前子项。
- 蓝图页用 `selectedTaskID` 表示当前选中节点。点击节点先选中，再可编辑或添加下级；顶部输入区显示「添加到：主任务 › … › 当前任务」，切换节点时同步更新目标，避免固定 `focusTaskID`。
- 事项列表和卡片菜单增加「编辑」「添加下级任务」「查看任务树」；去掉 20 层截断，深层缩进使用可横向滚动或层级标识避免挤压标题。蓝图布局按父子分支排列，避免简单按全局索引排布导致深树难读。
- 验收：从根、子项、孙项新增时都落在被选中的父项下；列表、蓝图、四象限立即同步；键盘、VoiceOver 能读出当前层级和添加目标。

### 阶段 4：iOS/iPadOS 入口和呈现

- 在 `IOSTaskDetailView` 增加父任务路径、直接子项列表、编辑与添加下级入口；继续使用 `NavigationStack`、`Form` 和 sheet。点击子项进入该项详情，支持继续添加下一级。
- iPad 使用相同数据与操作，按可用宽度展示，不限制触控目标；检查 Dynamic Type、深色模式、长中文和 VoiceOver。
- 验收：iPhone/iPad 上完成「主任务 → 子任务 → 孙任务 → 编辑孙任务」流程，退出并重启后结构和内容不变。

### 阶段 5：回归和交付

- 单元测试：增添三层以上结构、父子循环拒绝、移动子树、删除中间节点、不同层级进度、跨蓝图/依赖约束、编辑后 ID 与工作流字段保留、备份/同步往返。
- UI 走查：空树、有数据树、已完成节点、已取消节点、长标题、大字号、浅/深色、Reduce Motion、键盘与 VoiceOver。检查 AI 图片生成后的同一编辑路径。
- 每次代码修改后运行 `zsh scripts/build-app.sh` 并打开 `dist/序.app`；另编译 iOS/iPadOS Simulator 目标。把各阶段页面映射与验证结果记入 `rollout.md`。

## 建议的交付顺序

先完成阶段 1 和 2，让编辑与新增下级在数据层可靠；随后完成 macOS 的选中目标与入口，再接 iOS。每阶段都交付可操作的实际界面，并对已有用户任务做回归验证。

已接通现有任务的编辑和多级子任务创建：macOS 卡片、分类、任务详情、任务蓝图及旧蓝图检查器有明确入口；iOS 详情可编辑并逐级打开下级任务。父子关系写入验证、删除中间层的提升语义、深层列表显示和持久化往返已有测试。跨蓝图整棵子树迁移尚未提供界面，当前会阻止含下级任务的单项蓝图迁移，以免产生不一致归属。
