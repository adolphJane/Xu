# 任务为基础，蓝图 / 列表 / 四象限为视图

这是 macOS 任务添加的产品与实现边界，回应“添加主任务和子任务后自动转为蓝图模式”。[交互设计稿](mockups/task-entry-macos-subtasks.html)演示保存后的视图切换，使用演示数据，不修改当前业务模型。

## 一条任务，多个入口和视图

**`TaskItem` 是用户创建与完成的基础实体。**主任务和子任务各有稳定 ID，子任务通过 `parentTaskID` 指向主任务。分类、安排日期、象限、完成状态仍是任务属性；列表、四象限、蓝图都读取同一批任务 ID，只改变组织与呈现，不创建“蓝图版任务”或复制完成状态。

| 视图 | 读取同一任务的方式 | 首屏重点 |
| --- | --- | --- |
| 列表 | 按日期/分类筛选任务；有子任务的主任务可展开或收起其子项 | 快速扫描、完成与编辑 |
| 四象限 | 按任务自身 `quadrant` 分组；子任务保留自身象限，默认可继承主任务 | 决定优先顺序；不改变任务身份 |
| 蓝图 | 以主任务和 `parentTaskID` 形成任务树；已有执行依赖作为另一种连线叠加 | 看目标、步骤、先后关系与进度 |

一条子任务改名或完成，应在三种视图立即反映。切换视图只修改当前展示状态；不迁移、复制或重建任务。只有一条主任务时可停留在当前列表；当保存了至少一条子任务时，默认关闭添加窗口并打开该主任务的蓝图视图，选中主任务节点。**“连续添加”已开启时保持输入焦点**，显示“已创建，可查看蓝图”入口，避免强行打断连录。

## 蓝图如何从任务结构出现

1. 用户输入主任务和若干子任务，保存前看到“将创建 1 项主任务 + N 项子任务”，主按钮变为“添加并查看蓝图”。
2. 保存主任务及子任务；子任务关联到主任务 ID。未设置独立蓝图的任务树也能在蓝图视图显示。蓝图标题取自主任务标题，不要求用户再填蓝图名称、目标日期或主题色。
3. 蓝图画布默认把主任务放左侧，子任务按录入顺序平行排列在右侧；**父子线只表示拆解关系，不代表执行阻塞或先后顺序**。如果用户明确设置前置关系，再用有方向的依赖线表示。
4. 蓝图的进度默认显示“已完成子任务 / 子任务总数”；主任务是否完成仍由用户决定，不因子任务全部完成而自动改变。
5. 返回列表或四象限时，使用刚刚创建的相同任务 ID，保留类别、排期和状态。子任务的独立计数应有清楚规则，避免同一视图同时汇总主任务与子任务时让用户误以为重复创建。

## 实施前的代码差距（已按下述策略落地）

当前 `BlueprintItem` 是单独的可持久化对象，包含名称、目标日期、状态、颜色；`BlueprintWorkflowView` 只读取指定 `blueprintID` 的任务，画布连线读取 `dependencyIDs`，自动定位也按依赖层级计算。`TaskItem.parentTaskID` 与 AI 子任务已存在，但仅凭父子关系**不会**让当前蓝图页面出现新图。因此不应把“给子任务写 `parentTaskID`”报告为功能已完成。

建议引入**蓝图投影/视图状态**：对没有 `blueprintID` 的结构化主任务，按根任务 ID 派生一张“任务蓝图”；对已经属于旧 `BlueprintItem` 的任务，仍在原蓝图内显示父子结构并定位该主任务，不再生成第二张同名蓝图。保留旧蓝图的阶段、里程碑、目标日期、状态、颜色及导入导出语义；它们作为额外的规划元数据，不成为另一套任务真相。旧蓝图即使暂时没有任务也应继续可见。

此投影需要分别调整蓝图入口/索引、画布取数、层级布局与导航目标；不能把 `parentTaskID` 直接塞进 `dependencyIDs`，否则完成阻塞规则会被意外改变。列表与四象限应逐步增加父子分组或标识，但不能为了“显示一次”而漏掉子任务的独立安排和完成状态。`BlueprintItem` 与旧 JSON/文件夹同步的兼容性需在实施时核对；本设计阶段不变更模型或格式。

## macOS 添加界面的对应变化

- 不再把“关联蓝图”作为普通任务首屏的必经决策；分类与安排仍可见，已有蓝图上下文由入口继承并显示。
- 子任务区保留回车连续添加。每条是 `TaskItem`，同时是蓝图中的步骤节点。
- 有子任务时，保存摘要和按钮说明将进入蓝图视图；无子任务时保留“添加任务”。
- 保存完成后用同一组任务更新蓝图、列表、四象限。任何动画都应支持 Reduce Motion；切换后将键盘焦点移到蓝图标题或主任务节点，让 VoiceOver 能读出当前位置。

## 验收样例

创建“准备新版首页发布”及两条子任务后：蓝图出现一个主节点、两个子节点与两条**层级线**；列表显示这三个任务的同一 ID 及父子关系；四象限按各任务象限展示；在任一视图完成一条子任务，其他视图同步变为 1/2。一个子任务改到不同象限时，蓝图中的父子关系保持不变。删除主任务时，沿用现有解除子任务父关联的语义并给出清楚确认。已有蓝图内添加子任务时回到该蓝图，而不新增独立蓝图卡片。
